# Prioritized reentry for confirmed observation candidates

The change creates a display-only priority group for candidates that previously reached a buy point but currently need confirmation again. It requires historical `BUY_CANDIDATE`, current `NEAR_ENTRY`, and a non-empty structure quality, then renders a dedicated UI group and requires fresh intraday confirmation. `BLOCKED` candidates are routed to the deferred/risk group, and the UI labels priority candidates without a current quote as awaiting a same-day review. **Watch for:** **confirmed** `TIGHTENED` and `HIGH_QUALITY_ONLY` candidates are accidentally excluded from prioritized reentry because the risk classifier treats the state-machine reason text `市场风险提高普通候选晋级门槛…` as a pausing risk.

**Verdict**: NEEDS_CHANGES

## High-level view

The presentation layer owns priority reentry. `isPriorityReentry` is consumed only by `ScreenFragment`, while notification eligibility still requires a real `BUY_CANDIDATE` and the existing guarded execution path. This keeps a displayed priority candidate from becoming actionable or generating an alert merely because of its position in the list.

The new risk split is intended to distinguish paused `BLOCKED` candidates from environments that merely tighten entry requirements. **confirmed** Its implementation mixes structured risk state with a Chinese-text keyword check, so valid non-pausing market-risk candidates can be treated as deferred based on their explanatory text instead of their actual risk level.

## Market-risk exceptions are lost during priority grouping

**confirmed** The predicate in `ObservationEligibility.isPriorityReentry` admits a historical buy candidate in `NEAR_ENTRY` with a non-`NONE` structure only when `isRiskOrDeferredObservation` is false. That classifier correctly treats `marketRisk == BLOCKED` as deferred, but it also returns true whenever `candidate.reason` contains `风险`.

`ObservationPool` assigns `市场风险提高普通候选晋级门槛，等待更强的日线承接或二波确认` whenever `environmentTightened` keeps a candidate in `NEAR_ENTRY`. `MonitorService` sets that flag for both `TIGHTENED` and `HIGH_QUALITY_ONLY`. A previously confirmed, structurally valid candidate in either non-pausing environment therefore fails the priority predicate solely because its explanation contains `风险`, contradicting the documented rule that these environments may retain the candidate for priority re-evaluation. The existing unit test proves that `BLOCKED` is deferred, but does not cover either allowed risk level or this reason-text interaction.

## Presentation remains separate from execution and alerts

The priority group is constructed only in `ObservationEligibility.prioritizedSections` and consumed by `ScreenFragment` to order and label cards. A priority candidate remains in `NEAR_ENTRY`; `ObservationBuyAlert.canNotify` still requires `BUY_CANDIDATE`, and the monitor's notification path still applies its guarded buy check. **confirmed** The priority-specific references do not introduce a state transition, an execution bypass, or a notification trigger.

## Fresh-market-data status is visible

For a priority candidate, `priorityReentryAwaitingFreshEvaluation` requires both a candidate evaluation and a quote dated today. `ScreenFragment` gives a candidate failing either condition the explicit label `曾确认买点，待当日行情复评` and states that it is not an executable participation basis. **confirmed** This prevents absent same-day market data from being presented as an immediately actionable reentry.
