# State-first candidate-pool display ranking

The candidate pool now keeps presentation evidence separate from the state machine’s 0–3 qualification `score`: it persists structure quality, relative strength, and market-risk snapshots, while rendering a real technical snapshot only when one exists. The UI divides candidates into BUY, NEAR, OBSERVING, and deferred/risk groups, then applies the requested intra-group order through `ObservationDisplayRankingPolicy`; sector role and strength only resolve an otherwise equal ordering. The service derives and persists the new display fields alongside the existing evaluation result, without changing the evaluator’s stage or notification calls. The UI passes `StrongSectorRankingPolicy.Result` to the display ranker’s board tie-break callback, which is the expected type.

Watch for: **confirmed** — a candidate whose persisted `marketRisk` is `BLOCKED` can still appear in the BUY group when its reason text does not independently match the risk keyword list.

**Verdict**: NEEDS_CHANGES

## High-level view

The new display policy correctly makes state the first ordering boundary, and it no longer converts the state machine’s qualification count into a technical or composite score. Within a state group, it orders structure, relative strength, market risk, an actual technical snapshot, review progress, then board role and board strength. This retains the intended separation between candidate evaluation and presentation.

**Confirmed concern:** the fourth-tier classifier recognizes breakout, limit-up, shrinkage, and reason-text risk signals, but not the persisted `ObservationMarketRisk.BLOCKED` value. The evaluator usually demotes that condition on a fresh evaluation, but the presentation boundary must also cover an already-persisted BUY candidate so it cannot be shown as actionable while its risk snapshot says ordinary promotion is blocked.

**Confirmed coverage gap:** the eligibility test checks a BUY candidate whose *reason text* says risk, but it does not check the persisted market-risk marker or directly exercise the full ranking precedence. `ScreenListUiTest` checks source text rather than rendered ordering. The missing cases leave the blocked-risk regression and ordering contract unprotected.

## A blocked market-risk snapshot can bypass the fourth tier

**Confirmed.** `MonitorService` persists `ObservationMarketRisk.BLOCKED` when the promotion environment blocks ordinary entries. `ObservationEligibility.prioritizedSections` then moves only candidates accepted by `isRiskOrDeferredObservation` to `deferredRisk`. That predicate checks `breakoutRisk`, limit flags, and a set of reason substrings, but does not inspect `candidate.marketRisk`.

```kotlin
val blockedBuy = candidate.copy(
    stage = ObservationStage.BUY_CANDIDATE,
    marketRisk = ObservationMarketRisk.BLOCKED,
    reason = "已确认",
)
```

This valid persisted representation reaches `ordinaryBuy`, so the UI renders it in the first group despite the `BLOCKED` snapshot. `BLOCKED` should join the fourth-tier predicate. `TIGHTENED` and `HIGH_QUALITY_ONLY` should remain separate decisions because the documented high-quality exceptions can still be valid candidates under those conditions.

## The primary invariant needs executable ordering coverage

**Confirmed.** The test suite confirms that structure can beat the old qualification `score` and that a reason-marked BUY goes into `deferredRisk`. It does not construct a `marketRisk = BLOCKED` BUY, nor does it test the comparator’s complete order. The UI test only asserts that implementation strings occur in `ScreenFragment.kt`, so it cannot show that a ranked candidate receives the expected group or ordering at runtime.

Add a compact unit matrix for `ObservationDisplayRankingPolicy` and `prioritizedSections`: one assertion per precedence boundary, an absent-versus-real technical snapshot case, and an equal-evidence pair where only `StrongSectorRankingPolicy.Result.roleScore` or `sectorScore` differs. This will preserve the required state-first order without reintroducing `score` as a presentation proxy.
