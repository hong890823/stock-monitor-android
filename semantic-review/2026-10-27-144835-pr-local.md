# 候选池的趋势复评与封板状态分层

这组改动把观察池从一次性晋级改为按策略和当前行情复评。启动前趋势路线继续以 `PRE_BREAKOUT` 入池；强势、涨停后稳定和二波路径由状态机留在待确认或晋级买点。已经确认过的候选在趋势未破时，遇回踩突破风险、资金流延迟或环境门槛会保留为等待确认，而封板和缩量只在当前行情仍封板时进入暂缓。展示层按“股票代码 + 策略”保留独立路线，并把封板/缩量的暂缓项固定放到第四档。**Watch for:** **confirmed，阻塞：**候选池回归测试当前有两项失败，分别反映三板历史确认轮次和已确认候选连续回踩的预期没有与新状态机同步。

**Verdict**: NEEDS_CHANGES

## High-level view

`ObservationPool` 使用 `highestStage` 识别曾到达买点的候选。只要趋势没有转弱或下行、没有高位派发和缩量加速，突破风险、资金流延迟与环境门槛只会降为等待确认，不再触发三日走弱或十日未确认淘汰。

封板状态以实时行情为准。封板时不能参与，开板后清除旧的缩量/封板状态并重新累积确认轮次；三板及以上延续路线需要三轮间隔复评。

候选展示按策略而非单纯代码去重，行键也包含策略。封板持续和封板/缩量暂缓不会再因板块强度进入“强势观察”，而是进入第四档。

## 已确认候选在趋势完好时保留复评入口

`ObservationPool.evaluate` 以 `highestStage` 判断候选是否曾经达到 `BUY_CANDIDATE`。新分支在趋势没有走弱、日线大趋势没有转下、高位派发未触发、且没有缩量加速时，将突破风险、资金流暂缓和环境门槛统一停在 `NEAR_ENTRY`。相同条件下，三日走弱和十日未确认的淘汰仅适用于从未确认过买点的候选。

这满足“回踩、资金流或环境暂缓不轻易淘汰”的目标。二波候选、整理和箱体结构也直接落入等待确认，二波确认且 `allowBuy` 时不再形成结构门槛，因此可走到正常确认路径。**[阻塞｜confirmed]**现有回踩测试仍要求第二轮风险把曾确认对象降至 `OBSERVING`，与这个保留策略相反，导致目标范围内的测试任务失败。

## 封板和缩量以当前报价闭合，再从开板重新确认

`ObservationEligibility.applyQuoteGate` 在有报价时只依据当前是否封板；开板即清理旧的封板和缩量标记，封板持续路线只保留一轮开板宽限给状态机消费。`ObservationPool` 对当前封板直接置为观察状态并清空确认轮次，恢复非封板后重新计算买点条件。涨停持续路线用保存的 `limitStreak` 决定确认轮数，三板及以上为三轮，普通强势路线为两轮。

启动前路线在趋势确认后可直接参与；多日强势和涨停延续路线必须经过新的间隔复评，缩量封板不会在封板时晋级。**[阻塞｜confirmed]**三板历史轮次的新定义与 `ObservationPoolStrategyTest` 的既有断言相冲突，当前精确测试执行失败；在明确“保存的历史连板身份”是否应跨开板持续生效前，这条晋级规则没有可通过的回归证明。

## 四档展示按策略隔离封板暂缓

`prioritizedSections` 先抽出 `LIMIT_CONTINUOUS` 和 `DEFERRED`，无论强势板块评分如何都只放进第四档；只有非暂缓的 `NEAR_ENTRY` 与 `OBSERVING` 才能进入第二档强势观察。`forDisplay` 改为按代码和策略去重，`ScreenFragment` 的行键与路线标签也改为策略级，两个策略的同一只股票将分别显示和翻页，不会由一条封板路线覆盖另一条已确认路线。

**[确认｜confirmed]**当前实现满足“封板/缩量暂缓不归入强势观察”和“同股票不同策略不互相覆盖”的展示约束。覆盖仍只证明通用强势/等待分组和策略分开出现在 `sections`；没有测试“暂缓项目即使 `isStrong` 为真仍在第四档”、策略级行键，或两条路线分别落在不同档位。
