# 可能主力动向的资金流证据汇总

The new assessment replaces the separate current-flow and three-day-flow detail rows with one directional label and its evidence on watchlist and portfolio cards. It combines the latest cached main-net percentage, a three/five-sample window, the super-large plus large-order buckets, and the displayed quote change. The UI presents the same assessment in both the waiting and analysed portfolio states, so any incorrect classification reaches all three surfaces. **Watch for:** **confirmed** stale or partial snapshots can be presented as today’s evidence; **confirmed** the large-order confirmation duplicates the main-flow measurement; **confirmed** sample count does not prove consecutive trading days.  
**Verdict**: NEEDS_CHANGES

## High-level view

**High, confirmed:** The policy discards invalid latest rows before selecting `current`. A provider response with a missing main-net percentage, or a failed refresh that leaves the cache intact, can therefore make an older row look current and pair it with a newer quote change.

**High, confirmed:** The claimed corroboration by “超大+大单” is derived from the same order-size buckets that define the provider’s main-net flow. Its lower threshold makes the second check redundant, while the wording treats it as additional evidence.

**High, confirmed:** The window continues to count stored rows rather than verified, distinct consecutive trading dates. That conflicts with the policy’s own stated rule that missing days must not be represented as a three- or five-day sequence.

## Cached snapshots can masquerade as current evidence

**High severity, confirmed.** `MainForceDirectionPolicy.kt:59-63` removes every row without a finite `mainNetPct` and then makes the surviving last row `current`. Thus a newly fetched but partial latest snapshot is silently replaced by a prior day’s complete snapshot. `MainForceDirectionPolicy.kt:67-70` validates only that selected row’s amount and sample count; it neither compares `current.tradingDate` with the quote used for `changePct` nor limits its age. The refresh path explicitly preserves the old cache after an error in `MonitorService.kt:1054-1057`, making the stale case expected rather than theoretical.

`facts()` subsequently calls the selected row `当日主力` at `MainForceDirectionPolicy.kt:192`, and `MarketFragment.kt:450-481` plus `PortfolioFragment.kt:437-477` and `490-513` display the assessment alongside the latest quote. The result can label Friday’s flow and Monday’s price as `主力进场` or `主力出逃`. Select the raw latest record before filtering, validate its finite fields and trading date against the quote date, and fail closed to `样本不足｜仅作观察` when the current observation is absent, partial, or stale.

## Three stored rows are not necessarily three trading days

**High severity, confirmed.** The policy promises that missing days will not impersonate continuous three- or five-day data, but `MainForceDirectionPolicy.kt:59-63` only sorts valid records and takes the latest five. It passes those rows to `FundFlowWindowPolicy` and prints `近3日` and `近5日` at `MainForceDirectionPolicy.kt:192-193` without examining `tradingDate`. Persistence caps history at five records (`FundFlowHistoryJson.kt:7, 45-54`), but it does not fill missed sessions or prove that retained dates are consecutive.

A user who does not run the monitor for one or more trading days can therefore receive a persistent-inflow/outflow direction based on non-adjacent observations. Build the window from distinct trading dates, validate it against the expected trading calendar, and either use dated wording such as “最近三个已采样日” or withhold the persistent classifications when a session is missing.

## The large-order check is not independent corroboration

**High severity, confirmed.** `EastMoneyFundFlowClient.kt:56-64` maps `mainNetYuan` from the provider’s main-flow field while separately mapping the super-large and large order buckets. `MainForceDirectionPolicy.kt:217-228` then defines the alleged large-order evidence as exactly `superLargeNetYuan + largeNetYuan`, normalized by the same turnover. The existing `FundFlowPolicy.kt:46-61` already describes main flow as the super-large/large-order net direction.

Consequently `MainForceDirectionPolicy.kt:82-85` tests one measurement twice, with a 3% main-flow gate and a 1% derived-bucket gate. For the provider’s order-size definition, a main-flow result over the first gate necessarily passes the second, so `INFLOW_CONFIRMED` and `OUTFLOW_CONFIRMED` claim corroboration that did not occur. Drop the redundant condition and describe the signal as a single main-flow measure, or replace it with a distinct source such as a time-series change, volume/turnover regime, or independently sourced institutional data.

## Incomplete buckets still support a directional label

**Medium severity, confirmed.** The `INFLOW_ABSORPTION` branch at `MainForceDirectionPolicy.kt:92-93` requires `!largeOutflow`. Kotlin evaluates that as true when `largeOrderNetPct` is null, so an absent super-large or large bucket can still produce `主力承接` as long as the window, main percentage, and price meet the other conditions. `MainForceDirectionPolicy.kt:177-183` reduces the confidence to `证据有限`, but does not prevent the named directional conclusion.

Require `largeOrderNetPct != null` and a compatible sign before applying a bucket-dependent label. If incomplete bucket data is acceptable for this branch, use a label that says the conclusion relies only on main flow and price rather than implying an order-size check.

## The classification matrix has no executable contract

**Medium severity, confirmed.** There is no `MainForceDirectionPolicy` test in `app/src/test/java`, despite nine labels, two threshold families, date/order assumptions, and nullable provider fields. The UI wrappers merely expose the policy result (`FundFlowDisplayPolicy.kt:53-57`), so UI tests cannot protect the classification semantics.

Add a focused table-driven policy test covering current snapshot date matching, a null latest percentage after valid history, stale cache, missing and duplicate dates, low-turnover rows, absent order buckets, exact 0.5%/3%/1% boundaries, and each direction/confidence outcome. Include display integration assertions that stale or partial state is rendered as insufficient rather than a directional summary.
