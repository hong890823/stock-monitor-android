# 优先复参与的风险分流

本次实现把曾达到 `BUY_CANDIDATE`、当前回落到 `NEAR_ENTRY` 且仍有结构的候选，单独排在待确认列表前面。`TIGHTENED` 与 `HIGH_QUALITY_ONLY` 仅收紧普通候选的晋级条件，当前已可保留在优先复参与；`BLOCKED`、封板、缩量和突破风险仍会被分流到第四档。优先标记只被展示层消费，通知仍要求真实的 `BUY_CANDIDATE`，缺少当日行情或当日复评时也会明确标为等待复评。Watch for: **likely** 启动前潜力路线把单次盘中跌幅判为 `trendWeak`，但没有同步写入风险标记或可识别原因，历史确认候选仍可能进入“优先复参与”，不满足趋势风险必须位于第四档的约束。

**Verdict**: NEEDS_CHANGES

## High-level view

收紧型市场环境已按结构化风险层级处理，而不是按“市场风险”文案匹配。`TIGHTENED` 和 `HIGH_QUALITY_ONLY` 的历史已确认候选保持在待确认内并优先复评；`BLOCKED` 仍是第四档的硬边界。

展示分组会先抽出封板、缩量、突破风险、明确的大趋势下行和高位派发等暂停条件，再拆分优先复参与。因此这些条件不会因历史买点或结构评分而被抬升。

**likely.** 启动前潜力路线额外用当日跌幅计算 `trendWeak`。这项实时走弱输入没有完整传递到第四档分类，导致优先复参与的风险边界在该路径上不闭合。

## 启动前潜力的盘中走弱没有闭合到第四档

**likely.** `MonitorService.buildObservationSignal` 对 `PRE_BREAKOUT` 同时计算 `trendWeak = trend?.trendWeak == true || quote.changePct <= -weakChangePct`，但只把 `trend?.trendWeak == true` 写入 `riskFlag`。当一只启动前潜力候选只是因当日跌幅跨过 `weakChangePct` 而走弱，且趋势策略本身尚未返回 `trendWeak` 时，`riskFlag` 仍为 false。

`ObservationPool.evaluate` 会因 `trendWeak` 拒绝确认买点，但仍可在 `confirmedEntry` 或资格分满足时把先前的 `BUY_CANDIDATE` 降为 `NEAR_ENTRY`；该分支的默认原因是趋势策略的简述或“条件逐步满足”，未保证含有 `isRiskOrDeferredObservation` 识别的“走弱”字样。候选持久化后也没有单独的 `trendWeak` 字段。于是 `isPriorityReentry` 只会看到历史买点、`NEAR_ENTRY`、非空结构及“非风险”分类，并把它放进优先复参与。

把 `riskFlag` 覆盖完整的 `trendWeak`，或把当轮实时走弱持久化为由 `isRiskOrDeferredObservation` 读取的结构化风险条件。修复后应以一个历史 `BUY_CANDIDATE`、结构有效、仅由 `quote.changePct <= -weakChangePct` 触发走弱的输入验证其最终位于 `deferredRisk`，而非 `priorityReentry`。

## 优先标记仍与执行和通知隔离

**confirmed.** `isPriorityReentry` 只由 `prioritizedSections` 和 `ScreenFragment` 用于分组、标签和“待当日行情复评”文案。状态机仍由 `ObservationPool.evaluate` 决定；`ObservationBuyAlert.canNotify` 仍要求当前状态为 `BUY_CANDIDATE`，所以 `NEAR_ENTRY` 的优先候选不会仅因标记而发出买点通知。

`priorityReentryAwaitingFreshEvaluation` 同时要求候选复评日期和报价日期均为当日。任一条件不满足时，界面显示“曾确认买点，待当日行情复评”，并说明其不构成可执行参与依据；无当日行情时的表达与实际门控一致。
