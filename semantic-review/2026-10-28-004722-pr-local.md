# Intraday T execution gates and net-profit filtering

The intraday T path now estimates a T sell using both trade legs, fees, slippage, and a minimum-net-profit threshold before exposing an executable quantity. The shared guard preserves the existing risk-reduction and exit branches, while T buy adds support, MA5/MA20, market-regime, bar-volume, and re-entry-capacity gates. The sell estimate is derived from the same lot-rounded quantity that the guard caps against today’s sellable balance, so a successful production T sell cannot exceed the amount priced by the estimate. Watch for: the production caller never supplies real re-entry capacity (**confirmed**); the claimed pullback-volume gate reads a live full-day ratio rather than pullback-phase evidence (**confirmed**); and the changed gates are not covered by matching tests, with existing assertions now inconsistent (**confirmed**).

**Verdict**: NEEDS_CHANGES

## High-level view

T sell now has a fail-closed execution path. A signal must carry an approved round-trip estimate, and the final guard uses its planned quantity after enforcing sellable shares and lot size. The risk-reduction and exit paths return before this T-specific logic, so the new profit rule does not change their quantity or priority.

T buy is deliberately fail-closed while re-entry capacity is zero. `MonitorService` builds the input without `reentryCapacityQuantity`, so `TradeNotification` blocks every production T buy even after a real manual sale has been recorded in the trade ledger. A real, attributable sell-minus-rebuy capacity source is required before this can become executable.

The two-stage volume check combines a current full-day, time-scaled ratio with a completed 15-minute bar ratio. The latter proves current-bar expansion, but the former cannot establish that the preceding pullback contracted because it is not scoped to the pullback window.

## Re-entry capacity never reaches the production T-buy input

`IntradayTactics.Input` adds `reentryCapacityQuantity` with a zero default and documents that a missing real sell record must remain zero. `TradeNotification` correctly uses that field, rather than total holdings or the planned T sell, and blocks `t_buy` when it is not positive. However, the production input constructed in `MonitorService` supplies ledger availability, but never supplies `reentryCapacityQuantity`; every evaluated T buy therefore enters the guard with zero capacity and remains observation-only. This is a **confirmed** functional gap: recording a real sell through `TradeLotLedger.sellToPortfolio` changes the lots and portfolio, but no code projects those records into the re-entry field.

The safe fix is to introduce a per-code, attributable T-cycle capacity that increases only from recorded eligible T sales and decreases only from recorded rebuys. Passing a generic current position, a risk-reduction sale, or the notification’s planned T-sell quantity would violate the requirement not to bypass real reduced-but-unreplaced capacity.

## The T-buy volume gate does not verify that the pullback was shrinking

`reentryObservationConfirmed` labels `input.volumeRatio <= 1.0` as “回踩阶段累计量比缩量” and pairs it with `barVolumeConfirming`. In production, that input is `Repo.volumeRatios[position.code]`. `VolumeRatio.of` defines it as today’s cumulative volume, scaled to a projected full trading day, compared with the 20-day average. It describes the observation moment’s aggregate session activity, not the bars that formed the pullback. `HoldingTObservation` retains price movement only, despite its tracker samples receiving volume, and `IntradayVolumeContext` exposes only the current completed bar’s relative volume.

This is **confirmed** to allow a T buy when a high-volume pullback is followed by a quiet-enough aggregate reading and one expanded current 15-minute bar. It can also reject a genuinely shrinking pullback after earlier session volume raises the aggregate ratio. Store a pullback-window volume baseline or classify the completed pullback bars before the rebound, then require that phase-specific contraction together with the current completed 15-minute expansion.

## New execution gates lack matching regression coverage

There is no direct test for `IntradayTNetProfitPolicy`, including commission minimums, both-leg slippage, the minimum net-profit boundary, or proof that its estimate quantity equals the final guarded T-sell quantity. The shared guard has T-sell defaults of `plannedTSellQuantity = 0` and `tSellNetProfitApproved = false`, but `TradeNotificationTest.intradayNotificationUsesGuardedTQuantity` still creates a bare `T_SELL` signal and expects “最多减300股”; it now returns an observation. This is **confirmed** without executing the test.

The existing T-buy evaluation fixtures also omit MA5, MA20, and `IntradayVolumeContext`, which the new `reentryObservationConfirmed` requires. Their `T_BUY` expectations now receive no signal. `tSellSkipsQuantityWhenTurnoverTooLow` also still expects `T_SELL`, although the changed strategy returns `T_SELL_DEFERRED` when sizing is zero. Update those tests and add production-path cases for a zero, valid, and exhausted real re-entry capacity; a high-volume pullback; and an estimate reduced by the final sellable cap.
