# 股票监控 Android 版

这是 macOS 菜单栏股票监控 `/Users/stephen/Desktop/A` 的 Android 原生迁移版。
**数据源、指标算法、信号判定与 macOS 版逐条对齐**，只把 rumps / AppKit / launchd
这些 macOS 专有能力换成 Android 的前台服务、通知与页面；刷新节奏在 macOS 版基础上按手机端
单独调过（行情 15 秒，详见「刷新节奏」）。

> 本程序不自动下单，行情与指标仅作条件式技术参考，不构成买卖建议。

### 数据源降级策略（与 macOS 版相同）

- **个股所属板块**（批次二新增）：东财 F10 `CoreConception` 的 `ssbk`。归属变化极慢，
  长缓存 15 天（`BoardTagCache`）+ 按需拉，不进 15 秒轮询；查不到就写「板块归属暂缺」，
  **不猜**。板块日线走 `push2his` 的 `kline/get`（与指数成交额同一端点形态），
  按板块码去重后各拉一次。
- 概念板块汇总（盘面总结用）：新浪优先 → 东方财富备用 → 上一次缓存。
- 概念板块榜（市场页卡片）：东方财富为主源 → 新浪概念板块兜底（两套分类口径不同，
  新浪也拿不到时才保留上次结果）。卡片下方会标出「来源 + 抓取时间」，
  结果同时落盘（`Store.conceptBoards`），重启后立刻有数据，不会空窗等下一轮 30 分钟刷新。
- 行业板块 / 涨跌停：请求失败**保留上次有效数据**，不覆盖、不伪造。
- 今日要闻：东方财富财经快讯优先，失败时用新浪财经快讯兜底；只展示上海时区当天发布的新闻。
  标题按宏观/政策、行业板块、公司事件关键词分类，分类只用于筛选和排序，不推断利好或利空方向。
- 涨跌停扫描结果为 0 时按非交易时段处理，保留上次数据。
- 瞬时网络抖动会重试 2 次（间隔 1 秒），仍在下一轮自动恢复。
- 涨跌停个股会按概念缓存标注所属板块（最多 3 个），与 `_build_board_map` 一致。

## 刷新节奏

一个基础 tick 为 **15 秒**（`MonitorService.TICK_INTERVAL_MS`），各功能点按自己的倍数执行：

| 功能点 | 刷新间隔 | 说明 |
| --- | --- | --- |
| 自选股 / 指数实时行情 | **15 秒** | 每个 tick 都请求 `hq.sinajs.cn` |
| 持仓股风险预警 | **15 秒** | 仅实际持仓数量大于 0 的个股：日内累计跌幅 -3% 预警、-5% 风险；较上次刷新急跌也推送，仅盘中 |
| 下探回升提醒 | **15 秒** | 大盘/持仓个股日内深跌后自低点回升（V 型收复）时推送，放量收复才震动，见下文 |
| 买卖点 / 做 T 提醒 | **15 秒** | 跟着行情一起判定，只在形态变化时推送，见下文 |
| 两市成交额 | **约 15 分钟** | 节流采样并按真实时刻落盘，用于跨日「同一时刻」对比 |
| 行业板块 / 概念板块 / 涨跌停 | **30 分钟** | 每 120 个 tick 一次（`SECTOR_INTERVAL_TICKS`） |
| 行业板块主力资金 | **5 分钟** | `f62` 主力净流入 + `f184` 主力净占比，仅作盘中辅助确认 |
| 选股 | **盘中不自动** | 需要时手动点：「重扫指标」（前200，秒级）/「深扫全市场」（趋势+513，几分钟）；盘后 18:00–06:00 自动全市场深扫一次，成功即停、失败 90 分钟重试最多 8 次，结果落盘 |
| 持仓分析 | **30 分钟** | 盘中一个槽位一次，盘后保留最后一次结果；也可在「持仓」页点卡片右上角「立即分析」手动重跑，不受槽位限制 |
| 持仓复盘 | **每天 1 次** | 16:00 收盘后自动生成并落盘，只缓存不弹窗；「持仓」页可手动重跑（不占自动档）；周末与节假日不生成 |
| 今日要闻 | **30 分钟** | 08:30–22:00 自动刷新公开财经快讯，也可在「工具」页手动刷新；失败保留最近一次有效结果 |
| 盘面总结 | **每天 3 次** | 16:00 / 18:00 / 21:00 各生成一次，只缓存不弹窗 |

- 只有工作日 08:30–16:00 才真正发起行情请求（`TradingCalendar.inRefreshWindow`），
  其余时段跳过网络请求，但仍执行定时任务（夜间指标刷新、盘面总结），与 macOS 版一致。
- 个股急跌阈值可在「设置」里调整（默认见 `Store.dropAlertPct`）；日内累计跌幅阈值固定为 -3% / -5%。
- 非持仓股（包括仅自选、仅观察池、持仓数量为 0 的股票）不推送个股跌幅、急跌、持仓信号或做 T 提醒；仅在观察池进入最高阶段“买点已确认”时按原有去重和预算规则提醒。待确认、观察中、暂缓参与和淘汰不推送。大盘提醒不受这一持仓过滤影响。
- **下探回升提醒**（`analysis/DipReboundEngine.kt`）：现有预警只管「跌下去」，这里补上对称的
  「跌下去又被买回来」——日内跌出恐慌坑后自低点回升且收复失地过半，就推一条。大盘阈值
  下探 ≤ -0.7%（创业板 ≤ -1.2%）+ 回升 ≥ 0.5%；持仓个股按 ATR% 缩放（约 1.2 个 ATR 日的砸盘，
  默认等价 -3% + 回升 2/3 下探幅度），个股限「持仓」且受买卖点开关 `intradaySignalEnabled` 控制。
  **「资金承接」看回升段成交节奏**（低点以来每分钟成交额 ÷ 下跌段节奏 ≥ 1.1 倍）——不能看全天
  累计成交额倍数，上午恐慌量会把缩量反弹也抬成「放量收复」。量能不缩 → 高优先级 + **震动**；
  量能缩了只给普通提醒、按超跌反弹观察。一段下探只提醒一次，创更深新低才重新武装，每码每天限 3 次。
- **板块主力资金**只修饰突破 / 回踩的确认文案，不单独触发买卖信号：板块上涨、成交额增速和主力净流入同向时增强确认；主力净流出时提示持续性打折。接口失败或数据过期时保留原有策略，不阻断提醒。

## 持仓波段加仓优先级

完整持仓报告顶部先展示“持仓整体操作建议”，按实际持仓汇总风险优先事项、深套机动仓处理、持有/止盈安排及是否追加资金，不要求每轮选出买入对象。持仓页的“今日要点”另有精简口径：结合总资金、剩余资金和持仓实时市值计算账户总盈亏金额/比例，后台使用总仓位与单股集中度判断整体建议，并只点名当前最值得优先操作的一只股票，不展示逐只仓位。工具页不显示持仓“今日要点”卡片。完整报告的逐股板块依据仍保留。

持仓页“今日要点”同时保留账户总盈亏和今日持仓盈亏。今日盈亏按当前股数乘以现价与昨收差额估算，比例以这些持仓的昨收市值为分母，不包含未录入的日内买卖收益或现金收益；与当天沪指比较时使用百分点差。缺少持仓行情只展示已获取部分，不进行完整对比；旧日期行情不冒充今日行情。卡片使用直白的动作描述，财务或公告风险展示实际分析原因，不把风险标签直接当作卖出指令；完整报告和复盘保持原有口径。

持仓报告默认按**几天到几周的波段**比较已有持仓：月K与250日线看背景、周K看方向、日K看回踩买点。顶部给出本轮首选、最多追加股数、分析价格、参考区间、风险失效价及加仓后仓位；不符合时明确“追加0股”。这不是全市场推荐，也不会自动下单或新增推送。

- 历史来自同一来源的前复权日线，请求1200根但不保证接口返回足量。2026-10-15公开接口抽查返回641根（2024-02-22至2026-10-15），界面按实际覆盖范围展示，不能宣称已分析五年。首个可能不完整周期、当前未结束周/月/年不参与聚合，年K仅作背景；250日线使用已结束的交易日。
- 最少需要250根已结束日线、24个完整周K和13个完整月K，并按基准指数最近30个已结束交易日逐日核对个股历史，缺失时不得拼接今日行情生成买点。要求周趋势向上、月趋势向上或修复、价格不低于250日线，并通过日线M20缩量回踩确认与至少2倍潜在盈亏比。封板、持仓破位/转弱/止盈信号、大盘或板块偏弱、基本面非“未见恶化”均不分配新资金。板块趋势缺失会明确标注；历史、现价或基本面关键数据缺失/过期则不给股数。
- **追加股数不是目标总持仓。**每轮只分配给一个首选，候补为0股；按分析价计算，受可用现金、现有仓位后的单股上限、本次追加上限（沿用初始仓位比例）、总资金1%的增量风险预算共同限制。费用预留至少5元或成交金额的0.1%，并非券商实际费率；风险预算也不保证跳空时损失封顶。
- 主板/创业板按100股递增，科创板最低200股后按1股递增，北交所最低100股后按1股递增。持仓市值与现金超过配置总资金、任何持仓现价缺失或参数无效时，全组合不分配新增资金。
- 在“持仓设置→设置资金”填写可用现金，默认0不会假定另有现金。额度基数取配置总资金与“已录入持仓市值＋现金”的较小值，用于追加比例、单股上限、风险预算及加仓后仓位计算，不让未核实资产放大股数。
- 深套不自动摊平，新增资金为0；原有机动仓做T建议与新钱加仓分开，没有真实减出记录就不推算接回数量。基本面风险不能用“等反弹做T”掩盖。
- 报告是带日期的分析快照，不是挂单指令。价格变化后股数和参考区间均须重新核实；持仓或资金配置变化会撤销页面上的旧数量建议。基本面沿用14天缓存并按需补拉，不改变既有持仓提醒和非持仓提醒范围。

## 盘中买卖点 / 底仓做T提醒

市场节奏采用**自适应压力**，不再用 `2.5 万亿`、`2 万亿`或“上涨第4～5天 / 下跌第7～8天”当硬门槛。成交额优先看**同一交易时点的相对倍数**，再结合行业/概念上涨宽度、指数方向、市场状态、短期趋势、MA20方向、近5日涨幅、ATR、MA5乖离；连续上涨/下跌天数只增加风险权重，不直接预测哪天分歧。同期成交额缺失时，才降级用“当前预估全天 ÷ 近期完整交易日成交额中位数”；市场宽度或个股延伸数据缺失时保持未知，不硬猜。下移高点、放量滞涨等结构证据优先于时间，可直接进入分歧风险。强势市场允许更深回落再做T，弱势市场更早提醒；动态回落系数为强市场 `2.0`、中性 `1.5`、弱势/风险 `1.0`，并继续叠加同板块龙头强势时的缓冲。真正卖出仍看趋势或关键结构失效，不因连续上涨天数、已经盈利或单日高成交额直接卖出。

每 15 秒跟着行情判定一次，命中就震动 + 通知（`analysis/IntradayTactics.kt` 判定，
`MonitorService.checkIntradaySignals` 触发）。支撑 / 压力 / 评分取最近一次持仓分析的结果，
实时价、量比、价格位置取本轮行情刷新已有数据；15/30分钟K线每5分钟刷新一次，两次刷新之间用
实时价更新当前未收盘柱。

### T+1 与 15/30 分钟确认

- A股执行 **T+1**：当天买入的份额不能当天卖出。这里的“做T”只指使用此前已持有的可卖底仓做日内回转，应用文案统一称“底仓做T”，不使用“T+0”。
- 交易批次账本区分**原有可卖仓位**和**今日买入锁定仓位**。A股当天买入的股票当天不可卖，
  所有卖出、减仓和做T股数均以“今日可卖”封顶并向下取整；只有当天新增仓位时提示停止加仓、
  下一交易日复核处置。旧持仓迁移后仍按原有数量可卖，未录入交易来源的手工加仓不会自动解锁。
- **15分钟是执行触发周期，30分钟是方向过滤周期。**普通买入、接回、普通止盈/减仓和做T必须有
  完整15/30分钟数据，且30分钟方向不向下；数据不完整或方向冲突时自动降级为“仅观察”，不继续
  展示可执行股数。风险卖出以15分钟风险结构为准，不等待30分钟过滤。
- 风险卖出优先级最高：跌破支撑、确认破位、高位转弱和退出优先一旦状态升级立即通知，
  不受普通盘中开关、10分钟同类冷却和每日机会预算限制；状态未变化仍只提醒一次。

### 资金流辅助证据

- “主力净流向”实际指大单/超大单主动买卖净流向，按订单规模归类，不代表已识别的机构身份。
- 每只股票最多保留5个交易日快照，分析报告同时展示当日、近3日和近5日；不足3日显示“样本积累中”，不据此改变判断。
- 资金流最多给技术评分加减1分，也可暂缓候选池晋级；不能越过价格、趋势、仓位、封板质量、开板次数和连续复评门槛。
- 资金流不进入 `IntradayTactics`，不影响盘中买卖、底仓做T、止损和减仓提醒。
- 符合封单质量、开板次数和连板条件的涨停股进入“涨停持续观察”；封板期间暂停超时淘汰，开板后按 15–45 分钟间隔重新走两轮确认，三板及以上需要三轮，并结合市场、板块和封板质量门槛。

做T增加两层证据（`analysis/HoldingTContext.kt`）：
- 复用持仓波段分析取得的前复权历史，只使用已结束日线，按指数最近30个交易日检查齐全性。用5日涨幅、5/10/20日均线和ATR区分趋势向上、连续拉升、修复、偏弱与震荡；周/月线复用已完成周期，只作方向过滤，不直接给买卖点。周期数据不完整时标为不足，接回确认更保守。
- 日线快照当日有效且最多保留45分钟；盘中至少3个成交量递增的有效样本、跨度至少60秒，检查最近3个价格是否连续回升/回落。最长观察窗口3分钟，超过90秒无有效更新、跨日、累计量回退均重新观察，重复行情不累加确认。
- 冲高回落幅度至少为 `max(0.5%, ATR%×0.25)`；接回观察要求量比在 `(0,1]`、近期观察未明显跌破支撑，回升至少为 `max(0.3%, ATR%×0.15)`。近期弱势或周/月方向不配合（含缺失）时回升门槛加倍；大盘/板块转弱或基本面红灯时不发接回机会提示。封板附近不发普通做T操作提示。这些阈值是规则筛选，不代表已证实资金承接或盈利保证。
- **同板块龙头强势会降低做T优先级，但不静音**（`IntradayTactics`）：**只认龙头，跟风小票不算**
  ——龙头强（封板，或炸板守住高位线）才说明板块还有空间。龙头仍强时，首次冲高回落只提示
  「板块状态参考｜冲高回落暂缓做T」并**不给减仓股数**。这里点名的非持仓龙头只用于解释同板块
  节奏，属于**非买卖指令**；回落加深到 `max(0.5%, ATR%×0.25) × 2` 才恢复给做T股数，正文写清
  哪几只龙头仍强、以及「回落加深到哪个价位」再评估。**龙头转弱立刻恢复做T提醒**：
  强弱用实时行情逐轮判（龙头代码跟着每 15 秒的行情一起拉），不留刷新窗口；
  信号按类型记跃迁，「暂缓做T → 做T」会重新推送。

### 板块龙头（`SectorLeaders` + `LeaderStrengthTracker` + `BoardGroupBook`）

- **名单跟着板块数据刷新（30 分钟一轮），不做盘中扫描**——龙头盘中不会变，逐轮扫成分股纯属浪费接口。
  只拉持仓实际归属的那些归类；成分来自东财 `EastMoneyClient.boardMembers`，人工改过则按人工名单。
- **默认＝归类内当日成交额前 5 名**（`SectorLeaders.SIZE`），排序用新浪成交额（与两市成交额同源）。
  不按流通市值排是因为东财市值字段没在线核实过。
- **「市场 → 📌 板块龙头」卡片逐行给每只龙头的现价、涨跌幅、成交额**（成交额来自实时行情），
  强弱标记：`🔴`＝此刻封板、`⚡`＝炸板后守住高位线（曾摸板且现价距涨停 ≤ 2 个百分点）。
- **「调整龙头」可手动指定 / 排除**：勾选=算龙头，把排名外的票提进来、或把自动挑中的踢出去；
  保存后**按你勾的来**，不再被自动排名改写（没勾的记进排除名单，免得它以后成交额上来了又被捞回来）。
  **长按个股可删除**（从板块成分和龙头候选中一并移除，随「保存」落盘）；「恢复自动」清掉人工修正，重新按成交额前 5 挑。
- **「板块管理」可改板块归类本身**（`BoardGroupBook`）：F10 的行业粒度经常和实盘的「同板块」对不上
  （中天科技挂在「通信设备」而不是「光通信」），所以板块归属以人的判断为准——
  弹窗分「我的板块」（点板块进成分股编辑）与「操作」（新建板块、编辑持仓归属、编辑持仓、删除板块 / 恢复自动成分）两区；
  - **改板块内个股**：勾选=归入本板块，勾掉的留在候选列表里随时勾回来，也可按代码/名称添加新股，
    **长按个股可从成分中删除**；保存后按人工名单挑龙头，「恢复自动成分」回到东财名单；
  - **编辑持仓归属**：把某只持仓改挂到指定板块（默认 F10 自动归属），龙头联动跟着新板块走；
  - **新建板块**（如「液冷」）：自定义板块没有东财板块码，成分股就是你添加的那几只；
  - **删除板块**：自定义板块可整组删除（挂靠它的持仓回到 F10 自动归属）。
- **强势判定是一个小状态机**（`LeaderStrengthTracker`）：封板、或今日曾封板（靠 `Quote.high` 反推，
  服务重启也不会忘）且现价距涨停 ≤ 2 个百分点算**强**；跌破高位线要**持续 3 分钟**才确认转弱——
  刚炸那一瞬的抖动不翻转，否则正好卖在回封前一秒。3 分钟门槛只放在「转弱」侧，转强不设门槛。
  展示标记（🔴 / ⚡）是纯计算，不做 3 分钟确认。
- 强弱用每轮实时行情现算，**不额外打接口**。龙头名单 10 分钟后当暂缺；
  **暂缺时退回原做T口径**，宁可照常提醒减仓也不因为缺数据把提示吞掉。
- 龙头家数与回落加深倍数都是规则筛选，不代表已证实板块还有空间。

主要形态（风险分级优先判断退出，其次高位转弱减仓；高位普通破位待确认不跳过确认）：

| 形态 | 触发条件 | 持仓时 | 空仓时 |
| --- | --- | --- | --- |
| 破位待确认 | 现价低于支撑 0.5% 以上，缺少持续或加重证据 | 提示风险、暂不加仓，不把第一次刺穿直接当清仓依据 | 不提醒 |
| 确认破位·分批减仓 | 持续未收回，或放量、跳空、大盘与板块同步转弱 | 非深套优先分批降低风险，不必等反弹；首次可评估减约1/3可卖仓位 | 不提醒 |
| 退出优先 | 已确认破位，且趋势转弱并失守自动风险参考，或叠加基本面红灯 | 核对证据后以退出为目标，可按流动性分笔执行；深套也不默认靠做T等待 | 不提醒 |
| 高位转弱·优先减仓 | 阶段高位叠加确认破位，或连续拉升后出现经连续行情确认的放量滞涨/冲高回落 | 优先分批减仓，暂停加仓与做T接回；不因高位直接清仓 | 不提醒 |
| 站回待确认 / 站回支撑 | 跌破后重新站回支撑上方 2% 内 | 未企稳与确认回升使用不同信号，避免后续确认被去重吞掉；不保证风险解除 | — |
| 反弹至压力 | 深套 + 基本面红灯，现价近压力 2% 内 | 评估分批离场，不用做T掩盖基本面风险 | — |
| 放量突破 | 现价 > 压力且量比 ≥ 1.3，并完成次日守住/回踩不破确认 | 提示继续持有、不追高 | 仅作观察，不直接提示买入 |
| 趋势延续观察 | 近期向上、周K向上、月K向上或修复，冲高仍近当日高位且未出现连续回落 | 保留底仓，不因固定涨幅机械卖出；与全市场强势环境事件分开 | — |
| 冲高回落·暂缓做T | **同板块龙头**仍强（封板或炸板守住高位线，小票不算），冲高后出现回落但未到 2 倍加深阈值 | 暂缓减仓、保留底仓，不给股数；正文列出强势龙头与「回落加深到哪」再评估；龙头转弱即恢复做T | — |
| 冲高做 T | 日涨幅达到原阈值，或多日连续拉升后当日上涨接近压力；还需放量/近压力及盘中回落确认；**龙头强势时回落须加深到 2 倍阈值** | 机动仓最多按持仓1/3测算且须有可卖股份，回踩企稳再评估 | — |
| 接回观察 | 达到回踩幅度、接近支撑，并通过近期走势与盘中连续回升确认 | 仅提示观察，不推算接回数量 | — |

- **卖出与接回分开**：做T减出上限按持仓1/3、整手向下取整；须自行核实A股T+1可卖数量。
  系统尚未记录真实卖出与接回成交，接回数量不得由当前持仓反推，也不假定之前提醒已成交。
  仅在确有减出时评估，不超过未接回的已卖股份及可用资金；需核对手续费、滑点，不承诺降低成本。
- **高位风险**：复用此前最多60个交易日的价格区间（至少20日），现价处于上1/3且相对区间起点涨幅至少20%才算阶段高位，不等同于历史最高价、估值高估或顶部预测。
  高位本身不触发减仓；确认破位时提高减仓优先级。未破位时，必须同时有近期连续拉升（日线涨幅至少 `max(6%, ATR%×3)`、近5个涨跌区间至少3次上涨）和至少60秒、3个有效样本的盘中连续回落。
  放量滞涨采用量比至少1.3、当日涨跌幅绝对值不超过1%、回落至少 `max(0.5%, ATR%×0.25)`；或回落至少 `max(1%, ATR%×0.5)`。缺位置、近期走势或连续行情证据时不启用未破位高位减仓。
  持仓报告、今日要点与盘中提醒共用风险政策；报告可复用同一份新鲜行情观察，不用单根日K冒充盘中确认。高位减仓期间不再同时推荐波段加仓或自动做T接回；普通深套规则不变，但深套不豁免已确认的高位转弱风险。
  低位不自动视为安全；清仓仍要求原有趋势失效或基本面风险与破位确认。以上为规则筛选，未证明盈利或最优卖点，不自动下单。
- **破位分级**：`HoldingExitPolicy` 同时用于持仓分析、复盘与盘中提醒，区分待确认、分批减仓、高位转弱优先减仓、退出优先。
  持续确认要求至少两个当日有效行情样本、累计成交量递增、跨度至少30秒；重复行情不累计确认，超过90秒间断或成交量回退重新确认。
  放量使用既有量比阈值1.3；跳空须昨收不低于支撑、开盘低于支撑0.5%且现价尚未收回；环境加重需大盘与板块同时转弱或塌陷。
  自动风险参考为支撑下方 `max(2%, ATR%×1.5)`，缺ATR时用2%；它不是用户事先录入的止损，也不是周线结构已坏的断言。
  当日同一监控会话的破位过程中固定支撑和风险参考，不随下一轮支撑下移；收回原支撑后重评。跨日、重启或关闭提醒后重新建立观察，不保存跨会话交易计划。
  风险参考失守需同时有趋势转弱与破位确认才升级退出；基本面红灯也须结合破位确认，缺失或过期基本面不当作恶化证据。
  深套普通破位仍可评估机动仓，但上述退出条件优先，不再默认无限等反弹；不假定之前减仓提醒已成交，不推算实际可卖数量。
- **深套阈值按波动率缩放**：约 8 个 ATR 日的跌幅（截断在 -12% ~ -30%，无 ATR 数据退回 -20%）。
  银行股亏 12% 就算伤筋动骨，题材股要亏到 30% 才等「疼」——固定 -20% 对两者都不公平。
- **基本面倾向参与破位文案**（`analysis/FundamentalHealth.kt`）：把最近一次基本面健康判断
  折成「亮红灯 / 中性观察 / 未见恶化」三级——评分 < 55、有 ALERT 风险项（立案处罚、财务硬伤、
  **业绩预亏 / 预减 / 下修公告**）、连续两季营收净利同比双降超 20% 算亮红灯；评分 ≥ 70 且无 ALERT
  且无周期口径提示才算未见恶化（周期股盈利高点的低估值是陷阱，再好也不说「未见恶化」）。
  深套按它区分风险处置与机动仓做T（红灯倾向离场，不把财务恶化当作普通回调），浅亏在减仓建议后补一句
  倾向（没数据也提示「基本面未分析」）；**只标倾向不替你拍板**——程序判断得了财务与公告可见面，
  判断不了行业景气与订单。**提醒只读缓存、从不在提醒时拉接口**：基本面是多接口合成的 F10
  数据，变化慢，缓存约半个月有效（`FundamentalHealthPolicy.CACHE_TTL_MS`），有缓存就用缓存；
  只对浮亏超 10% 或已破位、且没缓存 / 已过期的持仓后台补拉（`MonitorService.maybeRefreshFundamentalHealth`，
  失败 4 小时后再试）。**工具页手动分析和 AI 工具取过的报告也写进同一份缓存**
  （`Repo.publishFundamentalHealth`）：刚跑完分析提醒立刻能用，也不会再重复拉。
- **防打扰**：同一代码同一天机会类提醒（买卖点 + 下探回升）合计最多 8 条，破位风险及其升级不占此预算
  （`SHARED_PUSH_MAX_PER_DAY`），各策略自身的冷却与日限仍然生效。持仓股无论在不在自选里
  都会拉行情（早先批量加进持仓的也会触发盘中信号）。
- 做 T 阈值不写死 3%，而是**按板块涨跌停幅度缩放**（主板 3%、创业板 / 科创板 6%、北交所 9%），
  否则固定 3% 对 20% 涨跌幅的创业板几乎没有意义。
- **防打扰三层**：只在「形态发生变化」时提醒（条件一直满足不会一直提醒）；同一只股票同一类信号
  10 分钟内不重复；机会提醒每只股票每天最多 8 条。观察、减仓、退出使用独立类型，升级不会被低等级去重吞掉。
- 通知走独立的 `signal` 通道（`IMPORTANCE_HIGH` + 两下短震），可以单独静音、保留跌幅预警。
  开关是「工具 → 监控与提醒 → 打开设置 → 买卖点 / 做T提醒」，
  同一张卡片上的「试一次买卖点提醒」可以直接验证手机上是否真的震得动。

## 个股量比的口径

量比口径的唯一来源是 `analysis/VolumeRatio.kt`——个股报告、持仓报告、自选股与选股列表的量价标签
都调它，避免同一只股票在不同页面给出两个数字。`volumeRatioIntraday` 标记当前用的是哪种口径：

- **盘中**：`今日累计成交量 × (240 ÷ 已过交易分钟数) ÷ 20日均量`，即先把今日累计按已过交易时间
  折算到全天再比。不折算的话上午 10 点只走了 1/8 的时间，正常节奏的股票也会算出 0.1x，
  报告里的「缩量」结论和技术评分、持仓的「放量突破」判断都会被带反。
  折算分钟数有 5 分钟下限，避免开盘头几分钟放大成离谱数字。
- **收盘后 / 没有实时价**：`最近一日成交量 ÷ 20日均量`，纯日线口径。
- **隔夜与集合竞价（到 09:31）**：不计算量比。此时行情里的成交量要么还是上一交易日的全天量、
  要么只是当日集合竞价撮合的一小部分，两种含义都拿不到「今日累计」这个分子，硬算出来的极小值
  会把所有股票标成「缩量」。这段时间自选股与选股列表不出量价标签，个股报告退回
  「最近一日 ÷ 20日均量」的日线口径。
- 20 日均量取日线最近 20 根，并**显式排除当日**（`VolumeRatio.averageVolumeExcludingToday`）：
  日线序列带不带当日随时段和数据源变动（新浪盘中不含、收盘后补上，腾讯盘中起就带），
  不排除的话今天的量会同时出现在分子和分母里，量比会被系统性低估，
  收盘后报告与列表还会给出两个不同的数字。
- 个股报告、持仓报告、自选股、选股列表全部走这一份口径，同一只股票在任何页面都是同一个量比。
  与 macOS 版的差异：A 的公式是「最近一日 ÷ 最近 20 根均量」，收盘后那 20 根含当日、会重复计入；
  单测里的 A 数值对齐断言用的是历史日线（最后一根不是当天），因此不受影响。
- `analyze()` 的 `elapsedTradingMinutes` 默认 240（不折算），与 macOS 版参考实现一致，
  单测里的数值对齐断言依赖这个默认值；App 内调用都显式传 `TradingCalendar.tradingMinutesElapsed()`。

### 量价配合（自选股 / 选股列表 / 个股报告）

**量比单独看是二义的**：同样「量比 2 倍」，低位超跌时更可能是资金进场，已经涨了一大段之后则更可能是
借量出货。所以 `analysis/VolumePriceSignal.kt` 把量比、**当日涨跌幅**、**价格位置**三者组合起来判断，
自选股、选股列表、个股报告共用同一份结论。

**价格位置**（`analysis/PricePosition.kt`）用「近 60 日区间位置 + 累计涨幅」两个条件一起判，
只用区间位置的话，慢牛股天天都在区间顶部，会被系统性地误判成「高位」：

| 位置 | 条件 | 含义 |
| --- | --- | --- |
| 低位 | 区间下 1/3 且 60 日累计涨幅 ≤ 0 | 跌下来且还没涨起来，才算底部区域 |
| 高位 | 区间上 1/3 且 60 日累计涨幅 ≥ 20% | 位置高且已经涨多了，才是真的要防 |
| 中位 | 其余 | 位置上的倾向不明显，按中性处理 |

区间**不含当日**（与量比分母「20 日均量排除当日」一个口径）。位置只决定同样的量价组合往哪个方向解释，
不参与放量 / 缩量的计算。

| 量价 | 放量（量比 ≥ 1.3） | 缩量（量比 ≤ 0.8） |
| --- | --- | --- |
| **上涨** | `🔥 放量上涨`：位置不高＝资金进场确认（红）；位置高＝`⚠️ 高位放量上涨`，防冲高回落（橙） | `缩量上涨`：量减价升＝筹码惜售，属**持有**信号而非买点（灰）；`缩量弱反弹`（低位）多是无量反弹、不是吸筹；`⚠️ 缩量加速`（高位）多是控盘加速赶顶（橙） |
| **平盘（±0.5% 内）** | `低位放量滞涨`：区间低位且离低点还不到 10%，底部有量推不动，多为换手（灰）；`反弹遇阻滞涨`：同是区间低位但已从低点反弹 ≥10%（多在 20 日压力下方），更像冲高遇阻、等突破确认（灰）；`⚠️ 高位放量滞涨`：承接不住、借量出货（橙）；中位与位置未知＝`放量滞涨`（灰，不替用户判断方向） | 不标注 |
| **下跌 < 3%** | `放量下跌`：多空分歧放大、有人在接，低位偏承接、高位偏出货（灰） | `缩量阴跌`：没人接，还要磨到地量（灰） |
| **下跌 ≥ 3%** | `⚠️ 放量急跌`：恐慌宣泄、跌停被打开过，最值得盯次日确认（橙） | `⚠️ 缩量急跌`：多为跌停封死，抛压未释放，基本可划掉（橙） |

- **颜色只表示性质，不表示好坏**：红＝资金进场确认、橙＝需要警惕、灰＝中性提示。
  四种下跌组合都不是买点标记，区别只是「要不要继续盯」——硬分好坏反而会误导。
- 量比在 0.8~1.3、缩量横盘、拿不到实时行情或日线时都不标注（位置未知时不打高位警示，只给不带位置的文案）。
- 这段说明也写进了 App：`VolumePrice.helpText` 会显示在「市场 → 数据说明」和「选股 → 说明」两张卡片里。
- **自选股**：「市场」页一行保留成交额原值，成交额颜色跟着信号走，后面再补 `放量上涨 N.NN倍` 这类标签。
  位置每轮 tick 用实时价重算，区间每天取一次日线。
- **选股**：严格档与宽松档每一行用「名称 + 价格 + 当日涨跌幅」三列布局（与自选股一致），
  价格与涨跌幅都是当日的，指标后面再追加同一套量价标签。量比与位置都在扫描末尾单独取一次实时行情来算
  （`IndicatorScreener.fillLiveData`）；取不到就整行不显示标签、涨跌幅留空（`ScreenHit.changePct` 为 `NaN`），
  不影响选股结果本身。
- **个股报告**（持仓 / 个股信息）：`StockAnalysis` 用同一套位置口径改写量价信号，
  「高位放量滞涨」计 -1 分（中位与位置未知既不扣分也不加分），「高位放量上涨」不计买入加分，
  只提示防冲高回落；
  报告「二、量价关系」章节多一行位置说明，末尾直接给出量价那一句结论
  （低位还会按「贴底磨 / 已从低点反弹」分成换手与遇阻两种说法）。

自选股的 20 日均量与近 60 日区间每天只取一次（日线，每只股票一次请求），落盘在
`Store.volumeBaseline`（结构 `{"date":"...","source":"tencent-qfq","avg":{"代码":均量},"window":{"代码":[最低,最高,起点收盘]}}`），
重启后沿用当天数据不再重拉；拉取失败或只成功一部分时隔 15 分钟重试。
`source` 是日线口径标记，换数据源后旧缓存会因标记不匹配而自动失效、当天重拉一次，
否则除权股当天会继续沿用旧口径算出来的区间。
量比与位置本身每个 tick 随实时行情重算，所以盘中会跟着行情走。

## 趋势、高位结构与交易门控

系统同时输出短期趋势、大趋势和高位结构，三者都参与盘中提醒、观察池晋级、持仓分析和波段加仓判断：

- **短期趋势**：向上、连续拉升、修复反弹、向下、震荡、数据不足。
- **大趋势**：向上、向下、筑底、修复、数据不足。大趋势向下时只允许风险减仓/退出，
  普通买入、加仓、接回以及做T买入/卖出都禁止；数据不足时只观察，不分配新增资金。
- **筑底**：只能做底部反转观察或最多按初始仓位 **25%** 轻仓试错，不做正常加仓和做T。
  30分钟分歧、抗住和量能配合只是上涨趋势中的确认层，不能单独构成买入依据。
- **持仓结构保留**：`MA20` 仍上行、回踩未破坏结构且没有高位派发/突破下杀风险时，
  保留观察仓等待二波，不因已经产生浮盈就卖出。真正卖出看结构失效：低位或一般位置跌破 `M20`，
  高位或 MA5 乖离达到 8% 后跌破 `MA5`，或趋势转弱并失守风险参考；高位放量滞涨等派发证据优先减仓。
- **高位结构**：区分高位待确认、派发风险、整理蓄势、二波候选、二波突破确认和证据冲突。
  高位派发风险优先减仓/退出；高位整理或二波候选只保留底仓观察，突破并完成量能和周期确认前不买入。
  “高位横盘”本身不能区分涨不动和二波，只能给出概率性结构状态，不能预测随时下杀或必然二波。
- **缺失数据**：分钟K线、趋势历史、市场或板块数据缺失时，相关门控降级为观察，不把缺失解释成上涨、下跌或量能确认。
- **箱体结构**：用最近 30 根已完成日线识别箱体震荡、突破候选/确认、跌破风险/确认；
  箱体内和突破候选不晋级普通买点，只有突破获得量能确认后才重新进入正常趋势门控。
  箱体上下沿是统计区间参考，不是精确支撑压力，也不能保证突破或跌破有效。

筹码峰由成交量加权估算，只作参考，不代表真实逐笔筹码分布；提醒不自动下单，所有价格、数量和成交结果需人工核对。

### OBV 量价背离（个股报告第五节）

「OBV 近 20 日净变化为正」只说明区间资金总体流向，**不等于** OBV 跟上了最新股价高点——
价创新高时 OBV 有没有同步确认，才是判断上涨有没有增量资金的关键。`analysis/ObvDivergence.kt`
按经典定义判定两种背离（口径与 macOS 版 `obv_divergence.py` 逐字一致）：

| 判定 | 条件 | 含义 | 评分 |
| --- | --- | --- | --- |
| **顶背离** | 股价创阶段新高，但本轮 OBV **峰值**低于前期 OBV 峰值 | 价升量能没跟上，靠存量博弈，后劲偏弱（风险预警，不等于立刻见顶） | **-1** |
| **底背离** | 股价创阶段新低，但本轮 OBV **谷值**未再创新低 | 资金不再持续出逃，有企稳可能（不等于反转） | **+1** |
| 量价同步 | 创新高的同时 OBV 峰值同步创新高（低点侧镜像） | 量能配合，暂无背离迹象 | 0 |
| 信号打架 | 顶背离与底背离条件同时出现 | 多空矛盾，不作方向判断 | 0 |

- **比的是 OBV 自己的峰（谷）值**，不是价格高点当日的 OBV 读数——真实数据上两种口径会给出相反结论，
  「OBV 高点低于前期高点」的原意是比 OBV 曲线的两个高点。
- 段划分：本轮段起点＝两个价格高/低点之间的回撤/反弹极值；前期段起点＝前一个反向摆动点。
  摆动点＝±2 根 K 线分型极值（间距 ≥3 根）。
- 进行中高点（近 3 根内创窗口新高）单独标注「高点进行中，尚未走完确认窗」，
  否则实时场景（今天创本轮新高）会因确认窗没走完被整体漏掉。
- 报告给**可人工核对的对照数字**：前后两点的日期、价格、段内 OBV 峰值，
  用户可在行情软件里逐点核对「股价创新高 + OBV 是否同步」这两个条件。
- 数据不足 30 根、缺少可比的前期高/低点、股价未创阶段新高/新低 → 一律不加分、不硬判。

### 日线口径：前复权

2026-09 之前程序用的是新浪未复权日线（`CN_MarketData.getKLineData`），现已改为
**腾讯前复权**（`web.ifzq.gtimg.cn/appstock/app/fqkline/get?...&qfq`，`SinaClient.fetchTencentQfq`），
新浪那条只在腾讯失败时兜底。

原因：未复权在每次分红送转的除权日会留下一个向下的假跳空，把窗口内的最低价、最高价、
起点收盘价同时压低，位置判定、均线、支撑压力、MACD/KDJ 全部跟着偏移。实测中国神华
sh601088 在 2026-07-13 除权，未复权口径下除权之前每一天都比复权价高 1.03 元（约 2.5%）；
用程序自己的 60 日窗口（07-01~09-22）分别计算：

| 口径 | 区间最低 | 区间最高 | 起点收盘 | 区间位置 | 累计涨幅 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 未复权（旧） | 38.73 | 49.48 | 39.48 | 78.9% | +19.6% | 中位 |
| 前复权（新） | 37.70 | 49.48 | 38.45 | 80.7% | +22.8% | 高位 |

只差一个缺口，「中位」就翻成「高位」，量价标签与评分随之翻面。前复权还有个附带好处：
最后一根就是当前真实价，和实时行情天然接得上（后复权对不上，不复权有断层）。

三个需要注意的点：

- 前复权的历史价不是当年的真实成交价，除权股上支撑/压力与看盘软件的历史成交价对不上，
  但与看盘软件自己的复权序列一致。指数没有复权概念，腾讯对指数返回 `day` 字段的未复权序列，
  解析时自动区分（`SinaClient.parseTencentQfq`）。
- 腾讯返回的成交量单位是**手**，程序内部（新浪实时行情、20 日均量、量比分子）统一用**股**，
  解析时乘 100（`SinaClient.VOLUME_LOT`），否则量比会差 100 倍。
- 每次新除权，前复权的整条历史都会重算。程序的均量与区间缓存本来就是每天重建的，
  所以只需要 `Store.volumeBaseline` 里的 `source` 标记在换源时失效一次即可（见上文）。

### 选股的当日 K 线

日线序列带不带当日随时段和数据源变动：新浪（`CN_MarketData.getKLineData`）**盘中不含当日**，
最后一根是昨天；腾讯前复权接口盘中起就带当日。不对齐的话，盘中选出来的形态是「昨天收盘时」的形态，
列表里的「当前价」也会滞后一天（实测过：同一时刻自选股显示 11.95、选股列表显示 11.26）。

所以 `IndicatorScreener.withTodayBar` 会把扫描用的活跃股快照（这个接口本来就返回当日
`open/high/low/trade/volume`）拼成一根当日 K 线接到日线末尾，指标与价格都含当日。
收盘后日线本身已含当日，此时直接用日线数据，不再覆盖。量比的分母（20 日均量）则**排除当日**，
否则会被今天自身的成交量污染。列表里的价格与涨跌幅因此都是当日的，不再是昨天的收盘价。

注意这会让命中结果随盘中行情变化——同一天上午和下午扫描的结果本来就不该一样。

## 持仓复盘的口径

「持仓复盘」（`analysis/DailyReview.kt`）不是把盈亏数字再抄一遍——同花顺上就能看数字。
它回答的是**今天为什么赚/亏、现在什么状态、接下来怎么办**，每天 16:00 收盘后自动生成一份，
落盘在 `Store.lastDailyReviewText`，「持仓」页可以随时查看、手动重跑。

**规则生成，不调 AI**：文风可以硬，但每个数字都能在「持仓股」卡片和「📦 持仓信息」报告里逐条核对。
顶部统一展示“持仓整体操作建议”，后面保留两节复盘依据，每节末尾一行「结论：」：

| 章节 | 回答什么 |
| --- | --- |
| 持仓整体操作建议 | 原有仓位的风险、深套机动仓与持有安排，复用持仓报告和今日要点的建议生成逻辑；复盘未进行波段资金评估时不沿用旧买入股数 |
| 一、盈亏归因 | 今天赚/亏的钱主要来自哪只，贡献多大（**较昨收**） |
| 二、组合体检 | 总仓位、单股集中度、与沪指比、总浮盈浮亏（**较成本**）、风险点 |

原“个股技术面”整节删除，不再单列“操作优先级”。持仓信息报告也不再重复“波段加仓优先级”整段，具体价格区间、股数测算与依据留在逐股详情中。

几个刻意定死的口径：

- **两个口径全文分开**：「今日盈亏」是较昨收的日内浮动，「浮盈浮亏」是较成本的持仓浮动。
  每处都带口径后缀，两者不会在同一句里混着算。
- **贡献占比只在同号集合内算**：盈利股占「今日盈利」毛额、亏损股占「今日亏损」毛额。
  正负混杂且合计接近 0 时那个百分比会被互抵的分母放大成没意义的数字，那种日子**只给金额排序**
  并写明「贡献占比会失真」。同号集合里只有一只时也不写「占今日盈利 100%」这种废话。
- **缺数据写「未计入 / 暂缺」，绝不写 0**：没行情的股票不进分子也不进分母，只标出只数；
  成本没填全就说「算不出（不是 0）」。
- **总仓位不跟「最大仓位」比**：持仓设置里的「最大仓位」是**单股**上限
  （`DeepLossPolicy.suggestedAddQuantity` 用它算单股补仓余量），不是总仓位上限。
  总仓位只按满仓/重仓/半仓/轻仓分档描述，单股集中度才和「最大仓位」比。
- **节假日不生成**：没有节假日表，靠指数行情标注的交易日期判（`DailyReview.isTradingDay`）；
  不是今天就提示「今日非交易日」，**不覆盖旧报告**——不能伪造一份「今日」。
  拿不到交易日期时放行，让「全部缺行情」兜底，别因为一个缺失字段把每个交易日都挡掉。
- **自动档失败不自动重试**（避免每 15 秒重打），日期戳先落再跑，需要就手动点「重跑」。
  手动触发**不写日期戳**，否则下午手动跑一次会把 16 点的自动档顶掉。
- 与盘面总结同一约定：**只缓存不弹窗**，生成文档不推送通知，只有可操作的行情事件才震动提醒。
- 整体建议复用 `PortfolioAnalysis.overallAdvice`，按既有信号、基本面风险和深套状态汇总，不重算买卖信号，也不重复逐股长文。

章节标题必须以中文数字开头、emoji 放在数字后面（`ReportSectionAssertions` 的正则要求
`^[一二三四五六七八九十]+、` 才能切出章节），每节最后一行顶格写「结论：」。`DailyReviewTest`
锁住上述口径，改文案前先跑一遍。

## 技术分析的环境层（大盘 / 板块 / 较昨日）

技术面不能是「个股自洽」的孤岛：**熊市塌陷**时支撑位会被系统性击穿，「回踩支撑企稳」是接飞刀；
**板块集体塌陷**时个股独善其身的概率很低。所以判定分四层——**个股 × 板块 × 大盘 × 时间**。

**市场状态**（`analysis/MarketRegime.kt`，大盘与板块**共用同一套口径**）：

| 档 | 条件 |
| --- | --- |
| `BULL` | 站上 MA20 且 MA20 五日斜率 ≥ +0.1% |
| `NEUTRAL` | 其余 |
| `WEAK` | 跌破 MA20 且 MA20 五日斜率 ≤ −0.1%（等价旧的 `MarketFilter.HEADWIND`） |
| `COLLAPSE` | 跌破 **MA20 且 MA60**，且（近20日累计 ≤ −8% 或 近5日 ≤ −5%） |

日线不足 30 根判不了，写「暂缺」不猜方向。`TrendEntryStrategy.marketFilter` 改成薄封装
（`WEAK`/`COLLAPSE` 都映射到 `HEADWIND`），`MarketFilter` 枚举名不动，旧的选股缓存才读得回来。

**判定必须有后果**，否则白判：

| 场景 | NEUTRAL | WEAK | COLLAPSE |
| --- | --- | --- | --- |
| 空仓试仓 / 买入观察 | 正常 | 不开新仓 | 不开新仓 |
| 持仓「持有观察」 | 不动 | 趋势转弱，暂缓加仓 | **反弹减**，不补仓、不做 T 接回 |
| 深套新增资金补仓 | 不自动追加 | 不追加 | 不追加 |
| 破位等反弹离场 | 可以 | 可以 | 保留 +「反弹高度有限，别等太久」 |
| 做 T 接回观察 | 需近期走势及盘中企稳确认 | **不提** | **不提** |
| 破位减仓 | 正常 | 正常 | **正常**（塌陷期更该减） |
| 复盘风险点 | 正常 | 提示 | 第一条 = **系统性风险，先降整体仓位** |

**板块**（批次二）：个股所属行业查东财 F10 的 `ssbk`
（`emweb.securities.eastmoney.com/PC_HSF10/CoreConception/PageAjax`）——这是唯一能查到
「某只股属于哪个行业」的入口，现有 `sectors()` / `conceptBoards()` 只有板块自身涨跌和一只领涨股。
`ssbk` 里混着**地域**（贵州板块）、**风格**（消费风格）、**规模**（大盘股/权重股）、
**属性**（行业龙头）和**来源**（东方财富热股），`SectorContext.isIndustry` 会滤掉它们——
把「贵州板块」当行业去比涨跌会得出完全错的结论。归属**长缓存 15 天**（`BoardTagCache`），
按需拉，不进 15 秒轮询。

板块自身趋势用板块日线判（`push2his.eastmoney.com/api/qt/stock/kline/get?secid=90.BKxxxx`，
端点形态与 `indexDailyAmounts` 一致），走同一个 `MarketRegime.evaluate`。

**板块修饰**分三种，不能说成一句话：个股强/板块弱 = 独立行情、持续性存疑；
个股弱/板块强 = 掉队、问题在自己；板块塌陷 = 别指望个股独善其身。归属查不到就写
「板块归属暂缺」，**不猜**。

**结论怎么写**（这次一起定下来的约定）：

- **结论必须带上做出判断所依据的数字**。只写「当前 PE 不高」「盈利质量较好」是教科书话，
  PE 3 和 PE 19 读出同一句话；写成「PE 12.3 倍」「毛利率 62.0%、净利率 30.0%」，读者才核对得了。
  OBV 背离同理——「价升量能没跟上」是定义，得写出**差多少百分比**才判断得了这个背离值不值得当回事。
- **不写固定词典**。按 signal 名 / 状态名查表的解释（「状态含义：当前没有明确的加仓或减仓信号…」）
  同一信号永远同一句，已整段删掉；「应对」里带着这只股当天的数字和环境，信息量高得多。
- **「中性」档不能写成「自行取舍」**——那是不作为。要说清**程序为什么分不出来**
  （行业景气与订单它看不到），用户才知道该拿什么补。
- **`TechnicalResult.action` 字段不动**：它与 macOS Python 参考逐位对齐
  （`StockAnalysisReferenceTest` 有 `assertEquals`）。环境改写只在**报告渲染时**做。

**个股技术分析报告**（工具页 / AI 工具取的那份）也接了环境层，但**不传 `env` 时一字不改**——
`StockAnalysisReferenceTest` 与 macOS Python 参考逐位对齐，动了默认文案就破基线。传了才做两件事：

1. **报告头**写清「市场环境：塌陷——…」「板块：半导体｜板块今日 -3.2%｜板块塌陷」
   （放在头里而不是新增章节，免得打乱「一、二、…」的编号与结构校验）；
2. **就地改写**那些塌陷期会说反话的结论——不是加一句备注，而是把正文那句改掉：

   | | 默认 | 塌陷 |
   | --- | --- | --- |
   | ADX 结论 | 回踩不破均线**可以继续持有** | 但大盘塌陷：回踩不破均线**也别加仓**，『持有』只是别割在恐慌位 |
   | 行动计划 | 回踩不破 MA20 **可以继续持有** | 但大盘塌陷：回踩不破 MA20 **也别加仓**，冲高优先减 |

   理由：备注会被当成补充说明，正文那句「可以继续持有」照样会被照做。

个股报告还有「较上次分析」（评分 / 支撑 / 压力 / 量比的变化）。它**不叫「较昨日」**——
个股报告是手动触发的，上次可能是三小时前，快照存在 `AnalysisReportCache` 里并带时刻。
没快照写「无上次快照，写不出变化」，不硬编成「没变化」。

**较昨日**（时间维度）：`Store.portfolioSnapshot` 存今天 + 上一交易日两份状态快照
（信号/评分/支撑/压力/现价/当日涨跌/量比），`PortfolioSnapshotJson.rollForward` 只在**跨天**时
把上一份降级成「昨日」。报告里写「较昨日：评分 +1→+2｜支撑 8.50→8.62｜量比 0.9→1.5｜
信号 持有观察 → 减仓风险」；没变写「与昨日无变化」；没快照写「无昨日快照」——
**没数据和没变化是两回事**。

**话术**：持仓股的「应对」从「买不买」改成**加 / 减 / 不动**三档，每句嵌当天实际数字
（涨跌幅、量比、较支撑/距压力百分比），所以天天不一样，不再是「暂不做激进操作，观察支撑与压力」
这种模板。破位后的观察、减仓与退出收在 `HoldingExitPolicy`，
`PortfolioAnalysis` 与 `IntradayTactics` 共用同一份分级和行动文案；深套阈值仍由 `DeepLossPolicy` 计算。

## 两市成交额的口径

成交额这块做过两次修正，方案见 `analysis/TurnoverTracker.kt`：

- **不再拿「今日实时累计」直接比「昨日全天总额」**。那样比盘中必然恒显示大幅缩水，没有参考价值。
- **优先实时对实时**：直接取东方财富分时接口（`push2his.eastmoney.com/api/qt/stock/trends2/get`，
  `secid` 为沪指 `1.000001` 与深成指 `0.399001`），拿到 1 分钟级的分钟成交额，累加即得累积曲线。
  `ndays=2` 一次就能同时拿昨日全天与今日实时，因此**当天即可对比**，不用等第二天。
- **兜底**：接口取不到时，用本地盘中采样（`Store.turnoverSamples`，只保留最近 20 个交易日）
  跟「昨天同一时刻」比。今天记录下来的采样就是给明天用的。
- **全天预估**按「今日累计 ÷ 昨日同期 × 昨日全天」推算，比按已过交易分钟数线性外推更贴近真实节奏；
  09:40 前不出数，昨日同期占比不足 2% 时退回线性外推，避免给出离谱数字。
- 界面上会同时标出**真实采样时刻**（如「09:52 采样」）与数据来源可信度，方便判断这条对比是否可用。

### 比较双方必须落在同一钟表时刻

15 分钟只是「多久记一次」的节流，**不能当比较键**。取昨日同期一律用真实采样时刻
（`Snapshot.sampleMinute`）去查曲线，落盘的 key 也是真实分钟数（`09:30 = 570`）。

早先按向下取整到 15 分钟的槽位起点取昨日同期，分母会系统性偏小：成交额曲线早盘极陡且全天
单调递增，而分子是采样那一刻的实时累计。服务在槽位中途启动、或 tick 因网络请求漂移时，
采样落得越晚虚高越厉害——实测 2026-10-19 09:52 采到的今日累计（3921 亿）去配昨日 09:45
同期（3349 亿），全天预估会算出 **1.82 万亿**；按同一时刻（昨日 09:52 为 4177 亿）对齐后
是 **1.46 万亿**，与同花顺一致。同一原因也会把「较昨日同期」的涨跌方向带反。

顺带两条防线：昨日曲线末条采样要落在收盘（15:00）之后才算「全天成交额」，
半日截断的日子当空档，不进历史、也不当预估基数。

## 启动与退出行为

- **打开应用**：`monitorEnabled` 默认开启，进入主界面即启动前台服务并显示常驻通知。
- **划掉最近任务卡片**：服务声明了 `android:stopWithTask="false"`，划掉后后台监控继续运行；
  需要在设置里关闭「后台持续监控」或点击「停止后台监控」才会停止。
- **设置里「强行停止」**：不会自启，直到你手动再打开应用。
- **系统因内存紧张回收进程**：返回 `START_STICKY`，系统可能按自己的节奏重新拉起服务
  （国内 ROM 的「一键清理」行为不一）。这是后台监控能连续运行的前提。
- **开机 / 应用升级**：`BootReceiver` 会检查设置，但「开机自动启动」**默认关闭**，
  需要时在「工具 → 监控与提醒 → 打开设置」里手动开启。

除上述机制外没有任何保活手段：没有 `AlarmManager`、`JobScheduler`、`WorkManager`，
也没有多进程互拉。

Material 3，四个底部 Tab，涨红跌绿：

- **选股**：布局跟着两套刷新逻辑走——「扫描状态」卡（状态/进度/结果缓存时间）+「指标两档·快扫」

  只保留已确认、量能达标、未转弱且大盘非逆风的回踩M20/次日守住突破结构，按原优先级排序最多20只；
  回踩确认优先，突破确认仍只观察，不直接等于买点。新趋势深扫无命中则清空，旧缓存恢复也按精选规则收紧；
  已在持续观察池的记录不因精选缩减而直接删除。盘中不自动扫描；盘后自动全市场深扫一次。
  宽松预警保留原名，要求MACD改善必选、RSI<45或低位K>D至少一项；沿用现有M20破位标准过滤
  （低于M20超过2%，或连续两根K线收盘低于各自M20超过0.5%），不要求已形成买点。
  三项齐全优先，再按DIF非负、KDJ条件、指标完整性排序，最多20只；不再优先更低RSI。
  旧缓存缺少破位检查记录的宽松候选不恢复，需重扫；本轮无宽松命中则清空，已有观察池记录不删除。
  513 形态是短线事件：确认超过 3 个交易日的不再列出；严格档/513某档本次
  无命中时保留上次结果（列表各自保留，**超过 3 天自动清**，标注的保留时间是该内容自己的生成
  时间——指标两档与趋势+513 各记各的刷新时间）。结果落盘，重启后选股页仍显示上次扫描。
  选股结果还会进入「持续观察池」：启动前潜力池观察趋势修复、突破和回踩确认；强势龙头池从
  涨停候选开始，近期涨停与相对大盘强度仅作为观察资格；可走 M20 缩量回踩企稳或趋势延续持股两条路径，且必须满足趋势结构及有效风险价位。
  强势龙头的市场和板块环境只作背景记录，不作为硬拦截；普通候选仍保留市场过滤。候选准入坚持“不破位优先”：
  低位或一般位置以 M20 作为破位参考线；高位或现价较 MA5 乖离达到 8% 时改用 MA5 作为更紧的风险线，
  跌破所选风险线超过 0.5% 就不晋级或继续确认。
  再经过同一交易日两轮新行情复评（至少间隔 60 秒，超过 5 分钟中断重计，累计成交量须增加），才进入“买点已确认”。
  这只是技术条件，不证明资金承接或龙头地位；突破延续或二波确认后，若跌破突破参考位，或从日内高点快速回落并伴随放量，
  会降级为“突破延续下杀风险”，停止追买，持仓优先风险处置。
  两类候选独立评分、独立显示；连续 3 个交易日走弱或观察 10 个交易日仍未确认会自动淘汰。
  所有未淘汰对象（含普通观察中）盘中每 60 秒尝试复评；当天已完成日线按代码缓存，实时 K 线使用原始成交量，避免重复时间折算。
  缺失、过期或无效价格不推进复评，非交易时段不累计新买点确认。行情到达时立即拦截涨停价附近的候选，
  不等待日线请求完成；封板对象不计入“买点已确认”数量。涨停且有效量比 ≤ 0.8 时按“缩量加速风险”
  降级观察（这是保守过滤规则，并非确定见顶判断）；量比按交易时间折算，均量剔除当日。
  开板但仍缩量上涨时继续观察，缺少量能数据时保留已有风险标记；只有完整复评重新满足入场条件
  才恢复买点提醒。普通缩量回踩不触发这条封板降级规则。风险标记会随观察池持久化。
  列表按“强势龙头”“启动前潜力”的顺序分组，各组只展示“买点已确认 → 买点待确认”两档；暂缓参与及其他观察对象仍在后台持续复评，不在列表展示。
  每个展示阶段独立分页（每页 20 只，支持前后翻页），分组标题数量只统计展示的两档。
  统计与阶段分组共用过滤口径，股票名称前不重复显示阶段名称；列表每行最多两行摘要，完整理由和四类证据点击查看。
  选股页的扫描状态、持续观察池、指标快扫、513 与趋势深扫、说明卡片均可点击标题展开或收起，
  默认展开；每张卡片独立保存状态，行情刷新、切换页面及重启后继续保留。
  每只候选还会保存最近 30 个交易日的证据快照，供后续纸上交易和策略绩效复盘使用；快照和纸上
  交易只用于验证策略，不代表真实成交或投资建议。候选首次进入“买点已确认”时自动记录 1 手
 纸上交易，后续触发止损或淘汰时自动平仓，选股页按“启动前潜力”和“强势龙头”分别显示闭合笔数、胜率、收益和回撤。
  观察池每只候选同时展示四类证据卡：支持证据、反向证据、尚缺信息和判断失效条件；证据与每日快照一起落盘，缺失数据明确列出，不把缺口猜成利好或风险。
- **持仓**：总资金/仓位设置、监控股票、**持仓复盘**、盘中信号与应对建议、买卖成本计算、**降低持仓成本买卖策略**。
  这里**不做纯盈亏数字列表**（同花顺上就能看），要的是判断和结论。
  「持仓复盘」把当日盈亏和技术面拼成一篇复盘文档，见下文口径说明；
  「📦 持仓信息」报告逐股那行的「较前一日」后面也会跟今日金额，两者共用 `analysis/DayPnl.kt`
  的同一套口径（较**昨收**的日内浮动，组合收益率分母用**昨日持仓市值**）。
  「买卖策略（降低持仓成本）」输入目标持仓成本后，结合趋势、支撑/阻力、MA20、波段区间和风险价，
  在回落补仓、冲高卖出后低位接回、分批减仓三类方案中给出优先策略；成本按原始成本减已实现盈亏和费用的
  摊薄口径估算，不等同于券商所有账户设置下的“买入均价”，执行后须按实际成交重算。
- **工具**：个股技术分析报告、自选股管理、今日要闻、盘面总结、监控与提醒开关。
  自选股管理默认仅显示总数、顶栏数量和添加/管理图标；管理面板内完整展示名称与代码，
  每行直接切换顶栏显示或确认删除。长列表在面板内滚动，添加仍使用原有股票搜索与顶栏设置。

「自选股」和「监控股票」是两套互不影响的列表：自选股（`Store.watchlist`）只做行情看板与
常驻通知顶栏，走 15 秒批量行情；监控股票（`Store.portfolio.positions`）才跑技术分析与信号，
盘中每 30 分钟单独取价 + 240 日线，也可以手动触发。最近一次「📦 持仓信息」报告会落盘
（`Store.lastPortfolioReport`），重启应用后仍能查看，正文里带分析时间。
默认开启「加监控股票时同步到自选股」——在「持仓」里
新增监控股票时会顺手补进自选股（顶栏显示为关，不会挤占常驻通知），免得「市场」页看不到它；
该开关在「工具 → 监控与提醒 → 打开设置」里可关闭。

这个同步**只对开启之后新增的监控股票生效**，早先批量加进「持仓」的不会自动回填。所以「市场」页
自选股卡片右上角有个「补齐监控股票（N）」入口：只要自选股缺少监控股票就会出现，点一下把缺的
按「顶栏不显示」补进去，补完按钮自动消失；自选股一只不缺时不显示这个入口。补齐的条目和普通
自选股一样，可以在「工具 → 自选股管理」里切换顶栏显示或删除。

常驻通知只放行情本身：标题是标记为「顶栏显示」的股票（价格百元以上取整，最多 3 只，超出用 `…` 省略），
正文是指数概况 + 两市成交额（含较昨日同一时刻的对比），展开后多一行 `HH:mm 更新`。自选股数量、
刷新间隔这类设置项不放进通知；已经出现在顶栏的指数不会在正文里重复一次。

长报告（技术分析 / 买卖成本 / 持仓 / 今日要闻 / 盘面总结）在独立页面用等宽字体展示，可复制、可分享。
自适应图标（含单色主题）位于 `app/src/main/res/mipmap-anydpi-v26/`，通知小图标为 `ic_stat_monitor.xml`。

### 港美股数据源配置

- 美股财务字段优先读取 SEC Company Facts；现价优先尝试 Twelve Data，未配置密钥时回退到 Yahoo / Nasdaq 公开行情。
- 港股暂使用行情源和已有公开接口；报告会显示实际数据来源、最新财务期间和缺失字段，不会用 A 股数据补齐。

```bash
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' \
./gradlew -PTWELVE_DATA_API_KEY='你的密钥' :app:assembleDebug
```

- 不配置 Twelve Data 也可以运行；SEC 财务请求与现有公开行情请求相互独立，行情失败时仍可生成没有现价和 PE/PB 的美股财务报告。

### AI 综合分析

- 「工具」Tab 的「AI 综合分析」支持输入 A 股/指数、港股或美股名称和代码。
- AI 会优先读取程序已缓存的技术面、基本面和港美股报告，再整理最近 K 线、成交量摘要，并尝试补充网络资料。
- DeepSeek 配置读取自 `local.properties`：`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`。
- 网络资料无法访问时仍会调用模型，但报告会把缺失数据作为限制条件，不把缺失内容当成利好。
- 当前 Android 端为个人测试直连方案；API Key 会进入 APK，正式分发前应改为服务端代理。
