# Stock Monitor 核心逻辑迁移总结

更新时间：2026-10-23

## 1. 范围与目标

本次改动覆盖行情、涨跌停、资金流、今日要闻、候选池晋级、持仓/自选股展示和选股列表。迁移目标是把“数据采集 → 风险过滤 → 观察晋级 → 展示/提醒”作为一套可替换的数据和规则层，而不是只移植 Android UI。

## 2. 总体数据流

1. 定时拉取实时行情、指数、涨跌停池、资金流和板块数据。
2. 数据先做来源、日期、有限数值和缺失值校验。
3. 原始数据进入各自策略层：量价、趋势、封板质量、资金流、市场/板块环境。
4. 候选池按状态机复评，只有满足全部普通买入门槛才进入“买点已确认”。
5. UI 只消费结构化结果；缺失数据显示“暂缺/样本不足”，不自行补造。

## 3. 数据源与降级

### 今日要闻

- 主源：东方财富新闻接口。
- 备源：新浪滚动新闻，仅在东财当日无可用新闻时使用。
- 展示的“来源”是新闻原始发布媒体，不等同于抓取渠道；迁移时应拆分为“抓取渠道”和“发布来源”。
- 新闻按关键词归类：宏观/政策 > 行业板块 > 公司事件 > 市场快讯，再按发布时间排序；卡片取前 5 条，详情页最多 20 条。
- 新闻链接必须保留为可点击 URL。

### 涨跌停池

- 主源：东方财富涨跌停池，字段包含涨停价、涨跌幅、封单金额、成交额、流通市值、开板次数、首封/末封时间、连板数和行业。
- 备源：新浪近似扫描。近似扫描只作为可用性兜底，不参与东财封板质量晋级。
- 涨停列表使用封板质量综合排序；跌停列表按跌幅升序，不强行使用涨停评分。

## 4. 封板质量与候选准入

`LimitCandidatePolicy` 只接受东财涨跌停池数据，并要求：

- `limitStreak >= 1`
- `openCount <= 1`
- `封单/流通市值 >= 0.5%` 或 `封单/成交额 >= 10%`

合格股票进入“涨停持续观察”；未合格涨停股进入“强势龙头”观察轨道，最多取涨幅前 100 只。封板期间：

- 状态固定为 `OBSERVING`。
- 不进入普通买点，不发普通买入晋级。
- 保留连续观察，不因观察天数超时淘汰。
- 开板后重新评估。

## 5. 资金流规则

资金流字段是“按订单规模归类的主动买卖净流向”，不能表述成已确认的机构资金。

### 单日资金流

- 价格上涨且主力净流向 >= 3%：`SUPPORTIVE`，最多加 1 分。
- 价格上涨但净流向 <= -3%：`DIVERGENT`，暂缓普通买入确认。
- 价格下跌且净流向 <= -3%：`RISK`，加强风险提示。
- 价格下跌但净流向 >= 3%：`ABSORPTION_WATCH`，只作潜在承接观察。
- 成交额小于 500 万或字段缺失：低置信度，不加减分。

### 多日资金流

- 保存最近 5 个交易日快照。
- 近 3 日平均净流向 >= 3% 且至少 2 日为正：持续流入，+1 分。
- 近 3 日平均净流向 <= -3% 且正向日不超过 1 日：持续流出，暂缓晋级。
- 样本不足 3 日：`ACCUMULATING`，不参与晋级评分。
- 任一低成交额样本使窗口低置信度，不使用窗口加分。
- 资金流只影响候选池晋级和分析文案，不影响盘中买卖/T+1 提醒。

## 6. 候选池状态机

状态：

- `OBSERVING`：观察中。
- `NEAR_ENTRY`：买点待确认。
- `BUY_CANDIDATE`：买点已确认。
- `ELIMINATED`：连续 3 个交易日走弱或观察 10 个交易日仍未确认后淘汰。

策略：

- `PRE_BREAKOUT`：启动前潜力，走趋势/形态确认。
- `LEADER`：强势龙头，走龙头承接确认。
- `LIMIT_UP_CONTINUATION`：涨停持续观察，封板期间只观察，开板后重新确认。

### 晋级确认

- 普通龙头/涨停开板候选需要 2 轮新行情复评。
- 三板及以上需要 3 轮。
- 两轮之间至少间隔 15 分钟，单轮确认窗口不超过 45 分钟。
- 不使用“累计成交量增加”作为确认条件；累计量会自然增长，必须使用时间分离的新样本和价格/趋势条件。
- 重新封板会清零确认轮数。

## 7. 市场与板块门槛（当前暂停执行）

规则代码保留以下风险阈值，但本轮默认暂停执行，不再阻断候选晋级：

- 上证或深证主要指数跌幅达到 0.8% 风险阈值。
- 跌停数量至少 20 只且多于涨停数量。
- 已知关联板块全部跌幅不小于 1% 的弱势条件（即全部 `<= -1%`）。

当前开关位于 `MonitorService.promotionEnvironmentGateEnabled = false`，因此市场/板块环境只保留为可恢复的策略能力，不再返回晋级拦截原因。市场偏弱但个股形成抱团强势时，不再因大盘或板块环境被统一卡掉。

资金流持续流出、价格趋势破位、高位派发、缩量加速、突破失败、封板质量偏弱等个股级风险仍然生效。市场、涨跌停或板块数据缺失时保持未知，不用缺失数据强行拦截。

## 8. 持仓、自选股与选股 UI

- 持仓股和自选股列表支持单项收缩/展开，以及一键全部展开/收起。
- 收缩态只显示核心信息；展开态显示代码、价格、评分、支撑/压力、量价、资金流、近 3 日资金流、入场结构、结构依据和失效/止损。
- 资金流金额统一格式化为“万元/亿元”，百分比明确是主力净流向占成交额的比例。
- 持仓股状态标识从好到坏：
  `🟢 买入确认 → 🔵 买入观察 → ⚪ 持有观察 → 🟡 持有/止盈观察 → ⚫ 趋势转弱观察/等待 → 🔴 减仓风险`。
- 选股列表按评分/优先级从高到低排序，每页最多 8 条。
- 涨停、跌停列表分别提供独立的批量展开/收起入口，并保持间距。
- 快扫的指标严格/宽松、深扫的趋势/513结果统一进入“持续观察池 → 启动前潜力”；卡片和展开详情均展示“入池去向”。
- “买点已确认”按策略列表展示：强势龙头、涨停持续观察、启动前潜力各自显示自己的“买点已确认/买点待确认”，不是脱离三类策略的独立列表。
- 观察池按状态卡控，主要展示“买点已确认”“买点待确认”和“涨停持续观察”；纯观察中、暂缓参与不进入该入口，因此原始筛选命中数与观察池展示数不必完全相等。

## 9. A 股交易约束

- 所有买卖文案遵守 `T+1`：今日买入不能今日卖出。
- 只有已有可卖底仓时才讨论“底仓做T”，建议数量不得超过实际可卖数量。
- 候选池“晋级”只是观察状态升级，不代表自动下单或成交承诺。

## 10. 持久化与兼容

观察池 JSON 需要保存：

- 阶段、评分、连续观察标记、封板阻断标记。
- 入场确认轮数和时间。
- 连板数、封板质量分、数据覆盖率、关联板块。
- 突破风险和证据列表。

旧数据缺少新字段时使用默认值，不猜测历史封板质量或板块归属。

## 11. 迁移实施顺序

1. 先迁移数据模型、日期/缺失值校验和 JSON 持久化。
2. 再迁移资金流、涨跌停、市场环境三个纯策略层，并用单元测试锁定阈值。
3. 接入候选池状态机和定时刷新服务。
4. 最后迁移 UI 展示、分页、展开/收起和文案。
5. 用历史样本回测晋级后次日、3 日、5 日收益、最大回撤、胜率和错过率，再调整阈值。

## 12. 逻辑复核结论

- 封板不直接买入、开板后重新确认、资金流只作辅助、缺失数据保持中性、A 股 T+1 约束均保持一致。
- 复核时发现旧候选状态在三板以上仍可能沿用 2 轮确认的问题，已统一通过 `ObservationPool.requiredConfirmationRounds()` 计算，并补齐回归测试。
- 本轮新增的 15–45 分钟确认、三板 3 轮和封板质量评分是风险收紧规则，不是收益保证。
- 市场/板块晋级负向过滤器已默认暂停，保留代码和阈值，后续可单独恢复。
- 需要另一个项目重点验证：资金流 3/5 日窗口、封板质量分位阈值、15–45 分钟窗口，以及是否需要恢复市场/板块过滤器。
- 当前环境无法完成 Gradle 全量测试；迁移项目必须独立运行单元测试、离线构建和实盘模拟。

## 13. 本轮优化操作清单

1. 将快扫严格/宽松、趋势深扫、513结果统一映射为 `PRE_BREAKOUT / 启动前潜力`，并在选股卡片显示入池去向。
2. 在观察池策略分组中明确三条路线和各自的确认强度，避免把“买点待确认”误认为全部是强势龙头。
3. 保持观察池按状态卡控，不把纯观察中、暂缓参与混入主要入场列表。
4. 将市场指数、跌停广度、板块同步转弱的晋级负向过滤器默认关闭，避免市场偏弱时误卡抱团强势候选。
5. 保留个股级风险门槛、资金流辅助评分、涨停封板/开板规则、三板 3 轮确认和 A 股 T+1 约束。
