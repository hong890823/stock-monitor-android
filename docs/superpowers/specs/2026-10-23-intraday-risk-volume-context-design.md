# 盘中风险与量价上下文迁移设计

## 目标

把 macOS 项目的盘中风险、量价上下文、T+1 账本和统一动作守卫迁移到 Android 项目。最终通知必须来自结构化交易意图和本地守卫，不能让旧文案重新放行未经确认的买入、卖出或做T。

## 架构

```text
日级分析 + 组合状态 -> DailyRiskContextCache
15/30分钟K线 + 当前行情 -> TimeframeEvidence
市场成交额 + 个股/15分钟量能 -> IntradayVolumeContext
                              -> TradeActionGuard
T+1 批次账本 ---------------> actionable quantity
                              -> TradeNotification
```

## 规则

- 日级风险按 `(code, quote trading date)` 缓存，跨交易日不复用。
- 只使用最新已完成 15/30 分钟槽位做确认；当前未完成K线不能参与量价形态或增加确认数。
- 风险阈值为 `clamp(0.5 × ATR15 / support, 0.5%, 1.5%)`，连续破位确认最多三根。
- 单根破位只报风险；两根进入首批减仓；三根只有 `CRITICAL` 才允许清掉当日可卖仓位。
- 下杀承接必须由当前15分钟量能确认，并满足下影线、收复中点和接近前收盘；它只把首批压到100股，不代表确定的主力入场。
- 买入必须同时通过个股量能、两市成交额、两根15分钟确认、30分钟不反向、突破距离、拒绝/冲高回落和失效价检查。
- 行情日期、K线、量能或账本数据缺失时只能观察或下一交易日处置。
- portfolio数量和批次数量不一致时 `actionable_sellable_quantity = 0`。
- 所有可执行卖量按100股整手向下取整，清仓也不生成零碎股。

## 验收

验收覆盖单根/两根/三根破位、承接形态、量能缺失、`CRITICAL`、买入降级、T+1、账本不一致、跨日缓存和未完成K线过滤。
