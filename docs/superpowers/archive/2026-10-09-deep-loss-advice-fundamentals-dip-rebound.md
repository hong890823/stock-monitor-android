# 深套应对、基本面健康与下探回升归档

**归档日期：** 2026-10-09
**项目：** `stock-monitor-android`
**依据：** 本轮多轮需求讨论：深套（成本 45 / 现价 30）破位仍被要求「先割一部分」不合理，应改为补仓 / 做 T 取向；基本面判断应参与建议且优先用缓存；大盘 V 型下探回升（大资金承接）应有震动提示。

## 一、深套破位的决策框架（`analysis/DeepLossPolicy.kt`）

- 深套阈值按波动率缩放：约 8 个 ATR 日的跌幅（截断 -12% ~ -30%，无 ATR 数据退回 -20%）。
  银行股亏 12% 即伤筋动骨，题材股要亏到 30% 才等「疼」，固定 -20% 对两者都不公平。
- 深套破位**不再喊「先割一部分」**，改为两套剧本：①逻辑 / 基本面已破坏 → 等反弹到压力位
  分批离场（不割在恐慌破位位）；②逻辑还在 → 破位处先不动，等缩量止跌或站回支撑后小仓
  补仓降成本，反弹冲高按「冲高做T」做波段，再创新低则取消补仓计划。
- 补仓参考股数 = 空仓试仓口径（总资金 × 初始仓位 ÷ 现价）的**一半**（`ADD_ENTRY_RATIO`），
  再受最大仓位和可用资金约束、按手取整；文案与数字一致（说小仓就给小仓）。
- 浅亏破位改为「反抽确认」：破位瞬间多是恐慌盘，先别急着割，**反抽站不回支撑再减**；
  站回会再提醒（见下），反抽失败再度破位才是减仓时机（文案区分「首次破位 / 再度破位」）。
- 新增两个盘中信号，补上剧本的执行时机：
  - `RECLAIM_SUPPORT`（跌破后重新站回支撑）= 剧本②的补仓窗口（给股数）；基本面亮红灯时
    改口「不补仓，站稳后等反弹按剧本①离场」；
  - `EXIT_WINDOW`（深套 + 基本面红灯、反弹至压力 2% 内）= 剧本①的分批离场窗口。
- 持仓分析「减仓风险」分支与通知摘要同步该口径；**破位分支优先于「趋势转弱」话术**——
  深套股几乎都跌破 M20，否则剧本永远被转弱分支盖住（复核中发现并修正的真问题）。

## 二、基本面健康分级（`analysis/FundamentalHealth.kt`）

- 三级：亮红灯 / 中性观察 / 未见恶化。**只标倾向、不替用户拍板**——程序判断得了财务与
  公告可见面（业绩、现金流、商誉、立案处罚、筹码），判断不了行业景气与订单。
- 亮红灯：评分 < 55，或 ALERT 风险项（含**业绩预亏 / 预减 / 预降 / 业绩下修 / 业绩预告修正**
  公告，比财报快一到两个季度），或连续两季营收、净利同比双双下滑超 20%（业绩变脸）。
- 未见恶化：评分 ≥ 70 且无 ALERT 且无周期口径提示（周期股盈利高点的低估值是陷阱，
  再好的评分也不说「未见恶化」）；最新一季双降但未连续两季压到中性。
- 深套两套剧本按分级标优先级（红灯倾向离场、稳健倾向补仓做 T）；浅亏在减仓建议后补一句
  倾向，无数据也提示「基本面未分析」，不沉默。
- **缓存优先**：提醒只读缓存、从不在提醒时拉接口。缓存约半个月有效（基本面变化慢，
  `CACHE_TTL_MS = 14 天`），有缓存就用缓存；仅对浮亏超 10% 或已破位、且无缓存 / 过期的持仓
  后台补拉（失败 4 小时重试节流）。工具页手动分析、AI 工具取报告与监控补拉写入**同一份缓存**
  （`Repo.publishFundamentalHealth`），刚跑完分析提醒立刻能用，冷却内不重复拉接口。

## 三、下探回升提醒（`analysis/DipReboundEngine.kt`）

- 现有预警只管「跌下去」，这里补上对称的「跌下去又被买回来」——日内跌出恐慌坑后自低点
  回升且收复失地过半即提醒。
- 阈值：大盘下探 ≤ -0.7%（创业板 ≤ -1.2%）+ 回升 ≥ 0.5%；持仓个股按 ATR 缩放
  （约 1.2 个 ATR 日的砸盘，默认等价 -3% + 回升 2/3 下探幅度）。
- 「资金承接」看**回升段成交节奏**（低点以来每分钟成交额 ÷ 下跌段节奏 ≥ 1.1 倍），
  不看全天累计——上午恐慌量会把缩量反弹也抬成「放量收复」（复核中发现并修正）。
  算不出节奏退回累计量比口径；无下跌段基线时宁可不判「放量」也不误震。
- 量能不缩 → 高优先级 + **震动**（走大盘风险通道 / 买卖点通道）；量能缩了 → 普通提醒、
  按超跌反弹观察。文案接深套剧本②：「可留意补仓/做T窗口，个股以收回支撑、企稳为准」。
- 防打扰：一段下探只提醒一次，创更深新低才重新武装，每码每天 3 次；个股版限持仓股、
  受 `intradaySignalEnabled` 开关控制；**持仓股无论在不在自选里都进行情拉取列表**。

## 四、优化落实与负优化修复

已落实：剧本②/①的执行信号、放量口径重做、波动率归一化、业绩预告信号、补仓股数减半、
浅亏反抽确认、持仓股覆盖、无缓存提示、跨策略每日预算（买卖点 + 下探回升每码每天合计 8 条）、
`PortfolioAnalysis` 深套/浅亏文案单测。

复核发现并修复的负优化：

- **共享预算会吞掉风险提醒**：机会类提示用完日预算后，破位提醒被静默丢弃——已改为
  破位（风险）提醒永远发送、不占预算，预算只挡机会类提示。
- **「下修」关键词误伤可转债**：「向**下修**正转股价格」被裸子串匹配成「业绩下修」误亮红灯
  ——关键词收紧到带业绩语境的写法（业绩下修 / 下修业绩 / 业绩修正），`GovernanceTest` 锁反例。
- **无基线假「放量」**：开在低点附近才启动时下跌段节奏为 0，任何回升成交都被判放量震动
  ——改为算不出就退回累计口径（宁可漏、不可错震）。
- 补仓数量不足一手的文案失实（说成「受仓位上限约束」）已更正。

## 五、明确保持的不变量

- 破位处不补仓接飞刀；补仓以收回支撑、企稳为准，再创新低取消计划。
- 基本面只标倾向，最终剧本选择留给用户；未引入投资建议口径。
- 防打扰三层（跃迁触发、冷却、每日限次）不变；15 秒行情节奏与数据源不变。
- 两套剧本的触发条件写进文案，不在恐慌 tick 直接喊任何单一动作。
