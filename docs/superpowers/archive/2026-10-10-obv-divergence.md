# OBV 量价背离归档

**归档日期：** 2026-10-10
**项目：** `stock-monitor-android`
**依据：** 用户用另一份 AI 核对个股分析报告，指出报告只给「近 20 日 OBV 净变化为正」不够完整——
它只代表区间资金总体流向，**不等于 OBV 跟上了最新股价高点**，答不了「股价创新高时 OBV 有没有同步」。
macOS 版已先行落地同一策略（`obv_divergence.py`），本轮回灌到 Android 版，口径逐字一致。

## 一、判定逻辑（`analysis/ObvDivergence.kt`）

- **顶背离** = 股价创阶段新高，但本轮 OBV **峰值**低于前期 OBV 峰值 → -1 分；
  价升量能没跟上，上涨靠存量博弈，后劲偏弱，属风险预警（不等于立刻见顶）。
- **底背离** = 股价创阶段新低，但本轮 OBV **谷值**未再创新低 → +1 分；
  下跌中资金不再持续出逃，有企稳可能（不等于反转）。
- 量价同步 / 中性不加分；顶背离与底背离同时成立 = 信号打架，净 0 分。
- **比的是 OBV 自己的峰（谷）值，不是价格高点当日的 OBV 读数**。这是实现中修掉的一个
  真实口径错位：初版按「价格高点当日 OBV 读数」对照，真实数据上判定与「OBV 是否同步创新高」
  这个核对条件会给出相反结论；教科书画法比的是 OBV 曲线的两个高点。
- 「OBV 近 N 日净变化」不能替代背离判定：区间累计流向为正 ≠ 跟上最新高点。

### 段划分与摆动点

- 摆动点 = ±2 根 K 线分型极值，间距 ≥3 根（±3 会在锯齿行情里漏掉末端高点）。
- p2 = 本轮高/低点，p1 = 其前的上一个高/低点；段内 OBV 峰（谷）值对照：
  本轮段起点 = 两个价格高/低点之间的回撤/反弹极值；前期段起点 = 前一个反向摆动点。
- **进行中高点**（近 3 根内创窗口新高）标 forming，判定行追加「（高点进行中，尚未走完确认窗）」。
  末端新高几乎总在确认窗内，只认已确认摆动点会永远漏掉「今天创本轮新高」这类实时场景。
- 摆动点不足（单边行情无回撤）退化为窗口极值对照；数据不足 30 根、未创阶段新高/新低、
  缺少可比的前期高/低点 → 一律不加分、不硬判。
- `currentPrice` 只参与「是否创新高」判断，OBV 对照仍取日线，实时价不改动历史摆动结构。

## 二、报告与摘要接入

- 个股报告第五节「波动与趋势强度」OBV 段扩写（不新增章节）：
  20 日净变化加局限标注 + **阶段高/低点对照行**（前后两点的日期、价格、段内 OBV 峰值，
  可在行情软件里逐点人工核对）+ 判定行 + 结论行 + 口径行。
- `TechnicalSummary` 新增 `divergence` 一行式结论，技术卡片（ToolsFragment）趋势行下显示；
  `GlobalFundamentalsReport` 量价行追加短标签。AI 分析走 `get_technical_analysis`
  拿的就是 `formatReport` 全文，自动覆盖。
- 评分接入在 action 计算之前（`score += divergence.scoreDelta`），否则建议分支会用旧分。

## 三、对拍金值更新（`StockAnalysisReferenceTest`）

对拍夹具 `kline_sh600089.csv` **正好触发底背离**（prior 2026-09-02 价 18.70 / OBV 3325204646
→ current 2026-09-16 价 17.83 / OBV 3387797264），因此金值同步更新：

- `score`：-2 → **-1**（实时行情 / 无实时行情两个用例、报告用例的「技术评分：-1」）；
- `action`：「技术面偏弱…」→「技术面中性：暂以观察为主…」（Android 的 action 是纯评分分支）；
- `signals`：「OBV近20日净变化为正…」之前插入「量价背离：底背离（股价创新低 OBV 未再创新低）」；
- 新增背离字段断言（state=BOTTOM、scoreDelta=1、对照点价格/日期/段内 OBV 峰值）；
- `TechnicalSummaryTest` 的 action 断言同步到中性分支。

## 四、验证

- 全量单测 **267 通过 / 0 失败**（新增 `ObvDivergenceTest` 9 例：平盘日 OBV 不变 / 量价同步 /
  顶背离 -1（含对照数字断言）/ 底背离 +1 / 进行中高点两态 / 未创新高 NEUTRAL /
  信号打架 CONFLICT / 数据不足 INSUFFICIENT）。
- 与 macOS 版交叉核对同一夹具：判定 BOTTOM / +1 / 对照点 18.70→17.83 两端一致。
- 报告排版过 `ReportSectionAssertions`（每节有结论行、章节数 10 不变）。

## 五、经验教训

1. **「N 日净变化」和「有没有创新高」是两个问题**：以后加任何「XX 为正/为负」类指标，
   先问它能不能回答「相对前期高点如何」。
2. **对照口径必须用真实数据冒烟**：合成数据上「当日读数 vs 段内峰值」两种口径几乎总一致，
   真实数据上会相反；判定与核对条件不一致时优先怀疑口径。
3. **两端对拍金值会被策略改动波及**：夹具数据落在哪个分支不是人工能预料的，
   改评分策略前先在参考实现上跑一遍夹具，把金值变化一次算准。
