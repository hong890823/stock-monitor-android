# 持仓复盘、技术分析环境层与结论口径归档

**归档日期：** 2026-10-12
**项目：** `stock-monitor-android`
**依据：** 用户三段递进的诉求：
1. 「想算出持仓股今日的盈亏情况」→ 做了「今日盈亏」卡后用户说**「单纯的数据我在同花顺上就能看，
   我想要的是一份报告，有盈亏也结合技术面做整体分析」**；
2. 「对于我持仓股票的分析**永远都是不建议买入等等一套相同的话术**，这个持仓的个股分析和整体分析
   是否足够合理呢？」，并接连补上「技术分析要考虑到**熊市塌陷**」「还要考虑**板块整体的情况**」；
3. 「刚才的策略针对个股技术面分析也进行了应用对吧」——查证后发现个股报告漏了，补上；
   又问「其它报告还有这种**僵化的教科书似的结论描述**吗」，遂全面清查。

今天的工作是一条线：**让技术分析从「个股自洽的孤岛 + 固定词典」变成「个股 × 板块 × 大盘 × 时间」
四层，并且结论必须带上判断依据的数字。**

## 一、从「盈亏列表」到「持仓复盘」（`analysis/DailyReview.kt`）

### 先做后删的「今日盈亏」卡

先按字面需求做了 `analysis/DayPnl.kt` + 持仓页「💰 今日盈亏」卡，用户明确否掉：
**「卡片就不要了，我在同花顺上就行，保留持仓观察信号和持仓复盘报告就可以」**。
卡片已删，`DayPnl` **保留**——它是复盘「盈亏归因」和「📦 持仓信息」报告共用的口径来源。

### `DayPnl` 的口径（`analysis/DayPnl.kt`）

- 今日盈亏 =（现价 − 昨收）× 数量，是**较昨收**的日内浮动；
- 组合今日收益率的分母用**昨日持仓市值**（券商 App 口径）。用今日市值当分母的话，
  涨得多的日子分母跟着变大，收益率会被系统性压低；
- 缺行情（停牌 / 未拉到）或昨收无效 → **不进分子也不进分母**，只计 `missing`，
  绝不拿 0 填充成「没亏没赚」；数量为 0 的观察股不进明细。

### `DailyReview` 四层结构

| 章节 | 回答什么 |
| --- | --- |
| 一、盈亏归因 | 今天赚/亏的钱主要来自哪只，贡献多大（较昨收） |
| 二、个股技术面 | 逐只趋势、量价、支撑压力，**今天这根 K 线改变了什么** |
| 三、组合体检 | 总仓位、单股集中度、与沪指比、总浮盈浮亏（较成本）、风险点 |
| 四、操作优先级 | P1 必须复核 / P2 收紧观察 / P3 止盈过热 / P4 不要动 / P5 等位置 |

**贡献占比只在同号集合内算**：盈利股占「今日盈利」毛额、亏损股占「今日亏损」毛额，
永不除以接近 0 的合计——正负相抵时那个百分比会被互抵的分母放大成没意义的数字，
那种日子**只给金额排序**并写明「贡献占比会失真」；同号集合只有一只时也不写「占今日盈利 100%」这种废话。

**章节标题必须以中文数字开头、emoji 放在数字后面**：`ReportSectionAssertions` 的正则是
`^[一二三四五六七八九十]+、`，`MarketSummary` 的「🟠 二、…」根本切不出章节（所以它没被这套断言覆盖）。
每节末行顶格「结论：」。

### 调度

每天 `hour >= 16` 自动生成一次（15:05 数据可能未定），日期戳 `Store.lastDailyReviewDate`
**先落再跑**——失败不每 15 秒重试，靠手动「重跑」；手动触发**不写日期戳**，否则下午手动生成
会顶掉 16 点的自动档。周末跳过；**节假日靠指数行情的 `quoteDate` 判**（`DailyReview.isTradingDay`），
不是今天就提示「今日非交易日」并**不覆盖旧报告**——不能伪造一份「今日」。
拿不到交易日期时放行，让「全部缺行情」兜底。**只缓存不弹窗**，与盘面总结同一约定。

## 二、技术分析的环境层

### 核心发现：原先是个股自洽的孤岛

核对代码后确认三个结构性问题（不是文案水平问题）：

1. **持仓股的「应对」只有 4 套模板，其中 2 套是一字不差的固定句**（「趋势转弱观察」「持有/止盈观察」），
   最大的「持有观察」桶只有 2 个变体——多数持仓多数日子都落在这里；
2. **`Store` 的 34 个 key 里没有任何历史快照**，结构上写不出「今天变了什么」；
3. **大盘状态只有一个出口，而且只管空仓股**：`TrendEntryStrategy.marketFilter`（沪指 MA20 + 五日斜率）
   只用来 gate `EntrySetup.confirmed/canBuy`，**已持仓股的四条建议完全不看大盘**；板块压根没接进分析
   （`MonitorService.buildBoardMap` 只认「概念板块领涨股」→ 板块名）。

### `analysis/MarketRegime.kt`（大盘与板块**共用同一套口径**）

「熊市塌陷」和「板块塌陷」是同一件事在不同尺度上，判定口径必须统一，否则两处会打架。

| 档 | 条件 |
| --- | --- |
| `BULL` | 站上 MA20 且 MA20 五日斜率 ≥ +0.1% |
| `NEUTRAL` | 其余 |
| `WEAK` | 跌破 MA20 且 MA20 五日斜率 ≤ −0.1%（等价旧的 `MarketFilter.HEADWIND`） |
| `COLLAPSE` | 跌破 **MA20 且 MA60**，且（近20日累计 ≤ −8% 或 近5日 ≤ −5%） |

日线不足 30 根**判不了**，写「暂缺」不猜方向。`marketFilter` 改成薄封装
（`WEAK`/`COLLAPSE` 都映射到 `HEADWIND`），`MarketFilter` 枚举名不动，旧的选股缓存（`ScreenResultJson`
的 `market_filter`）才读得回来。

### 判定必须有后果

| 场景 | NEUTRAL | WEAK | COLLAPSE |
| --- | --- | --- | --- |
| 空仓试仓 / 买入观察 | 正常 | 不开新仓 | 不开新仓 |
| 持仓「持有观察」 | 不动 | 不加仓 | **反弹减**，不补仓、不做 T 接回 |
| 深套剧本② 补仓 | 可以 | 更小、更快止损 | **整条压掉** |
| 破位等反弹离场 | 可以 | 可以 | 保留 +「反弹高度有限，别等太久」 |
| 做 T 回踩接回 | 可以 | 「先别急着接回」 | **不提** |
| 破位减仓 | 正常 | 正常 | **正常**（塌陷期更该减） |
| 复盘风险点 | — | 提示 | 第一条 = **系统性风险，先降整体仓位** |

### 板块（`analysis/SectorContext.kt`）

**归属接口**（用户「我也不知道是哪个接口」，实测找到）：
`emweb.securities.eastmoney.com/PC_HSF10/CoreConception/PageAjax?code=SH600519` 的 `ssbk` 字段，
返回 `BOARD_NAME` / `BOARD_CODE` / `BOARD_RANK`。

**关键是它混着非行业标签**：地域（贵州板块）、风格（消费风格）、规模（大盘股/权重股）、
属性（行业龙头）、来源（东方财富热股）。把「贵州板块」当行业去比涨跌会得出完全错的结论，
所以 `SectorContext.isIndustry` 按 `*板块`/`*风格`/`*股`/龙头/热股/融资融券/MSCI 滤掉，
主行业取滤后 `rank` 最小的那个。归属**长缓存 15 天**（`core/BoardTagCache.kt`），按需拉，不进 15 秒轮询。

**板块趋势**：`push2his.eastmoney.com/api/qt/stock/kline/get?secid=90.BKxxxx`，
端点形态与 `EastMoneyClient.indexDailyAmounts` 一致（close 在第 2 位），走同一个 `MarketRegime.evaluate`。

**板块修饰分三种**，不能说成一句话：个股强/板块弱 = 独立行情、持续性存疑；
个股弱/板块强 = 掉队、问题在自己；板块塌陷 = 别指望个股独善其身。归属查不到写「板块归属暂缺」，**不猜**。

### 板块在哪里能看到

| 位置 | 内容 |
| --- | --- |
| 个股技术分析报告 · 报告头 | `板块：半导体｜板块今日 -3.20%｜板块塌陷（东财F10）` + **个股 vs 板块**的相对判断（独立行情 / 掉队） |
| 持仓复盘 · 第二节「个股技术面」 | 每只股一行 `板块：半导体，板块今日 -3.20%（东财F10）` |
| 持仓复盘 · 第三节「风险点」 | 板块塌陷时：`板块塌陷：半导体——这些行业自己在跌，个股别指望独善其身` |
| 「📦 持仓信息」报告 | 每只股「状态：…」下一行的板块归属 + 涨跌；「应对」尾部还有三种修饰之一 |
| 持仓页「📦 持仓 / 观察信号」卡 | 「应对：…」尾部的修饰（独立行情 / 掉队 / 板块塌陷） |

> 分两层：**归属与涨跌**（`sectorNote`）是背景数据，**个股 vs 板块的相对判断**（`SectorContext.interpret`）
> 才是结论。后者只在「应对」尾部和个股报告头出现，前者在复盘与持仓报告里各有一行。

> **真机验证结果（2026-10-12 晚，五轮定位）**：
> - **归属通了**：`板块：电力设备（归属：东财F10）` —— `ssbk` 解析、`isIndustry` 过滤、主行业选取全部正确。
> - **板块日线没通**（`BOARD_CODE` → `90.BKxxxx` 或 `push2his` 板块 kline）。
> - **东财行业板块列表也拿不到**（`clist?fs=m:90+t:2` 返回空）。
> - **兜底最终靠人工对照表打通**：东财/申万式行业名（`电力设备`）与新浪 `newSinaHy.php`
>   自己的 50 个行业（`电力行业`/`电器行业`/`发电设备`）**是两套分类体系**，跨体系精确/包含
>   都匹配不上（「电子」还会同时命中「电子器件」和「电子信息」，模糊匹配本身就是错配）。
>   `Repo.SINA_BOARD_ALIAS` 30 条对照，特变电工 `电力设备 → 发电设备`，
>   报告标成「新浪行业板块「发电设备」（对照表）」——**是「最接近的行业」不是准确归属**。
>   实测取到 -0.27%，与本机直接拉新浪原始数据一致。

## 三、时间维度：较昨日 / 较上次

- **持仓侧**（`core/PortfolioSnapshot.kt`）：`Store.portfolioSnapshot` 存今天 + 上一交易日两份
  状态快照（信号/评分/支撑/压力/现价/当日涨跌/量比）。`rollForward` **只在跨天时**把上一份降级成
  「昨日」，所以「昨日」永远是上一交易日收盘的样子，不会被盘中多次刷新覆盖。
  报告写「较昨日：信号 持有观察 → 减仓风险｜评分 +2→-1｜支撑 39.20→38.60｜量比 0.90→1.85（放量急跌）」。
- **个股侧**（`AnalysisReportCache` 加 `snapshot` 字段）：个股报告是手动触发的，上次可能是三小时前，
  所以叫**「较上次分析」**而不是「较昨日」。
- **没快照写「无昨日快照 / 无上次快照」，不硬编成「无变化」——没数据和没变化是两回事。**

### 话术重写

持仓股的「应对」从「买不买」改成**加 / 减 / 不动**三档，每句嵌当天实际数字：

> 改前：「暂不做激进操作，观察支撑 8.50、压力 9.20 与量能是否继续配合。」
> 改后：「今天 +2.41%，量比 1.52·放量上涨，较支撑 +3.3%，距压力 7.4%——位置在区间中段，不动。
> 跌破 8.50 再谈减；站稳 9.20 再谈加。｜大盘转弱（…）：别加仓｜个股比板块「半导体」强 3.2 个百分点，
> 属独立行情，持续性存疑」

**顺带修掉一个符号 bug**：「离支撑」原用 `(support/price-1)`，方向反了，会让「贴着支撑」判断失真；
改为「较支撑 `+%+.1f%%`」（正数 = 在支撑上方）。

**深套两套剧本去重**：原先在 `PortfolioAnalysis.deepLossBreakAction` 与 `IntradayTactics.breakAction`
**逐字复制两份**，补仓股数说明也是两份。收拢到 `DeepLossPolicy.breakAction` / `addQuantityNote`，
两处共用；塌陷期剧本②的改写也只写一次。

## 四、个股技术分析报告接入（用户追问才发现的缺口）

查证结果：第一批只覆盖了持仓侧 + 盘中信号，**`StockAnalysis.formatReport`（工具页个股分析 +
AI 工具取的报告）一行环境代码都没有**。已补，但**不传 `env` 时一字不改**——
`StockAnalysisReferenceTest` 与 macOS Python 参考逐位对齐，动了默认文案就破基线。

传 `env` 才做两件事：

1. **报告头**写清「市场环境：塌陷——…」「板块：半导体｜板块今日 -3.20%｜板块塌陷」，
   外加一行**个股 vs 板块**的相对判断（`SectorContext.interpret(个股涨跌)`）——
   板块自身涨跌只是背景，独立行情 / 掉队 / 一起塌才是结论。
   放头里**而不是新增章节**，免得打乱「一、二、…」的编号与结构校验；
2. **就地改写**塌陷期会说反话的结论——不是加备注，是把正文那句改掉：

   | | 默认 | 塌陷 |
   | --- | --- | --- |
   | ADX 结论 | 回踩不破均线**可以继续持有** | 但大盘塌陷：回踩不破均线**也别加仓**，『持有』只是别割在恐慌位 |
   | 九、行动计划 | 回踩不破 MA20 **可以继续持有** | 但大盘塌陷：回踩不破 MA20 **也别加仓**，冲高优先减 |
   | 一、结论（无持仓假设） | 技术面中性：暂以观察为主… | …｜大盘塌陷：这里的『观察』是**别进场**，不是在等买点 |

   **为什么必须改正文**：备注会被当成补充说明，正文那句「可以继续持有」照样会被照做。

`TechnicalResult.action` 字段**本身一字不动**（参考测试有 `assertEquals`），
环境改写只在**报告渲染时**做，测试里加了 `assertEquals(..., technical.action)` 防回归。

## 五、结论写作口径（清教科书式描述）

用户问「其它报告还有这种僵化的教科书似的结论描述吗」，全量扫了 8 个报告生成器。

**发现并已清**：

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `PortfolioAnalysis.signalMeaning` | 按 signal 名查表的固定词典，每只股都印一遍「状态含义：当前没有明确的加仓或减仓信号…」 | **整段删除**（`PortfolioAnalysis.formatReport` 里注明了为什么删） |
| `GlobalFundamentalsReport` 4 个 conclusion | 「当前PE不高，但仍需结合增长速度…」——PE 3 和 PE 19 读出同一句 | 「**PE 12.3 倍、PB 4.5 倍**——按 PE 看不贵…」「**现金 56.6 亿、总债务 33.4 亿**；…（现金是债务的 **1.70** 倍）」 |
| `FundamentalHealth.tendency` | 「基本面中性（…）：两套剧本**自行取舍**。」 | 「基本面中性（**评分 60**，…）：程序在这一档**分不出优先级——行业景气与订单它看不到**，按你自己对这两项的判断在剧本①②里选。」末档也从残句变成「不构成加仓或减仓的额外理由，按技术面走」 |
| `ObvDivergence.meaning` | 「价升量能未跟上，上涨主要靠存量博弈」（**定义**，不是分析） | 「…本轮 OBV 峰值 **3,240** 比前期 **5,100** 低 **36.5%**…」——背离**差多少**才判断得了值不值得当回事 |

**已查但不动**：`FundamentalsReport`（A 股基本面，10 个 conclusion）**本来就是带数字的**
（「近 12 个月归母 812 亿、扣非 780 亿，两者相差 32 亿」「商誉占净资产 18.2%」「市值排板块第 3/42」）——
我一度把它误伤进「教科书」清单，读完正文后确认它合格，未改动。

### 定下来的写作约定（已写进 README）

> **结论必须带上做出判断所依据的数字。** 只给定性形容词（「不高」「较强」「偏弱」），
> 读者没法核对这个判断合不合理——换一只股读出同一句话，那这句话就没在传递信息。

配套四条：不写固定词典；「中性」档必须说清**程序为什么分不出来**；
`TechnicalResult.action` 因基线对齐绝不动；环境改写只在渲染时做。

### 「今日要点」精要（盘面总结 + 持仓报告）

用户提出：这两份最长的报告**恰恰最没有精要**——持仓报告十来段、盘面总结八节，想看
「今天要干什么」得翻到底。而个股报告有「一、快速概览」、AI 报告有「一、精要摘要」，
它们反而没有。

做法：把精要抽成**独立函数**（`PortfolioAnalysis.brief` / `MarketSummary.brief`），
**报告开头和持仓页卡片共用同一份**，口径只有一份。

- 持仓要点四块：**今日结果**（钱 + 跑赢跑输 + 主要来自哪只）→ **市场环境** →
  **要做什么**（按信号分档点名，**「今天不用动」也要点名**，否则用户会以为每只都得处理）→
  **风险点**（破位/深套/集中度/缺数据，只列有量的）。
- 盘面要点五行：大盘 / 量能 / 赚钱效应 / 主线与风险 / 结论。
- **结论那行与正文第八节的「核心结论」同一条口径**——两处给出两个判断，用户不知道该信哪个。

## 七、经验教训

1. **结论必须带判断依据的数字**——只给定性形容词，换一只股读出同一句话，这句话就没在传递信息。
   这条现在写进了 README。
2. **判定必须有后果**。`MarketFilter` 早就有大盘状态，但它只 gate 空仓新开仓，
   持仓建议完全不看——「有判定、无后果」等于没判定。
3. **两个口径永远分开**：较昨收（今日盈亏）vs 较成本（浮盈浮亏）。同一句里混着算，用户会看反。
4. **名字不等于含义**：`maxPositionPct` 计划里被当成「总仓位上限」，实际是**单股**上限
   （`DeepLossPolicy.suggestedAddQuantity` 用它算单股补仓余量）。动手前核对它在哪儿被怎么用。
5. **没数据 ≠ 没变化**。缺昨日快照时不能硬编「与昨日无变化」。
6. **模板插值的空格会被断言逮到**：`"$basis"` 两边加了空格，改写后的句子变成
   「回踩不破 **均线** 也别加仓」，原文没空格。同类：默认免责句里本来就有「市场环境」四个字，
   导致 `assertFalse(contains("市场环境"))` 误判——断言要锁**新加的那行**（带冒号），不是关键词。
7. **参考基线锁的是字段还是渲染要分清**。`StockAnalysisReferenceTest` 的 `assertEquals` 锁的是
   `TechnicalResult.action` **字段**，不是报告里那行——所以环境改写放在渲染层是安全的，改动字段才会破基线。
8. **误伤清单**：扫「教科书式结论」时把 A 股基本面报告也列了进去，读完正文才发现它本来就带数字。
   列问题清单前先读实现，别凭印象。
9. **诊断不能被兜底链吃掉**。给「拿不到数据」加的失败原因，如果写在中间分支而最终 `return`
   走的是兜底分支，用户看到的就只剩最后一层的那句话——**前两轮就是这样白跑的**：
   我据此推断「`push2` 是通的」，其实它返回的是空 map。失败原因必须落在**最终返回值**上，
   而且多级兜底要**把每一级的失败串起来**，不能只报最后一个。
10. **跨分类体系不能做模糊匹配**。东财/申万式与新浪的行业体系不同，「互相包含」会错配
    （「电子」同时命中「电子器件」和「电子信息」）。要么同源匹配，要么老实维护对照表
    并把结果标成「对照表」而不是精确归属。
