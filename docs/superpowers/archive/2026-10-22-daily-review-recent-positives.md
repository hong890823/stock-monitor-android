# 持仓复盘「近两日真利好」与利好词表收紧 · 归档

**归档日期：** 2026-10-22
**项目：** `stock-monitor-android`
**范围：** 持仓复盘新增近两日个股真利好清单；利好判定收紧为硬催化词表；回购注销改按占股本比例判定；利好窗口按交易日回溯。

## 一、结论

- 复盘报告新增「三、🔔 近两日个股重大利好」一节，逐条列出近两日个股的真利好落地公告（日期 + 类型 + 标题）；**更早的利好不列**——隔了几天的利好多半已兑现进股价，列出来是误导。原「强势环境暂缓做T记录」顺延为第四节，章节号不随条件跳号。
- 「利好」口径收紧为**真利好**（股价级别的硬催化）：重组落地获批（过户完成/交割完成/注册批复/同意注册/带重组语境的实施完成）、业绩爆发（业绩预增/大幅增长/扭亏为盈/业绩预盈）、中标、重大合同、大股东/实控人增持。
- **不算利好的**：分红/送转/股权激励、回购计划与回购实施完成、董监高小额增持计划、股权激励限制性股票注销；利空词一票否决（标题混「减持/处罚/立案/未中标……」直接不算）。
- **回购注销看占比不看金额**：披露的占股本/市值比例 ≥ 0.5% 才算（`BUYBACK_CANCEL_MIN_PCT`）。金额再大、占比 0.15% 不算；只报金额不报占比的宁缺勿滥不算。绝对金额口径已弃用——同样 5000 万对 50 亿和 5000 亿的公司是两回事。
- **窗口按交易日回溯**：从上一交易日收起——周一复盘自动收进周五盘后与周末挂出的公告（长假同理）；拿不到交易日表退回「今天 + 昨天」。节头如实写明实际窗口。
- 修复「实施完成」误判：此前「权益分派实施完成」「回购股份实施完成」会被撞成重组落地利好，现要求带重组/收购语境。
- 事件后蓄势（EventCoil）与复盘利好清单**共用同一份判定**（`EventCoil.positiveEventKind`），利好口径全 app 只有一份。

## 二、主要实现

- `analysis/DailyReview.kt`：`Inputs` 增 `recentAnnouncements`/`tradingDates`；`recentPositives`（窗口过滤 + 利好筛选，只看数量 > 0 的真实持仓）、`recentCutoff`（上一交易日回溯，表格不新鲜则兜底）、`recentPositiveSection`（公告暂缺 ≠ 无利好，分开写）。
- `analysis/EventCoil.kt`：`positiveEventKind(title, content)` 收紧为真利好词表；`ratioPct` 解析「占总股本/市值……X%」（取最大，净资产/总资产口径不认）；`wantsBuybackContent` 开放给正文拉取用；`trimTitle` 开放复用。
- `core/FundamentalsClient.kt`：回购注销候选加入选择性拉正文名单（占比只在正文里；此前只有治理重点公告拉正文）。
- `monitor/MonitorService.kt`：复盘输入传 `Repo.recentAnnouncements`（analyzePosition 已顺带补拉）与指数日线交易日表。

## 三、验证

- 全量单元测试 **796 条通过，0 失败**（较上期 788 新增 8 条口径锁）：近两日窗口过滤、交易日回溯（周一收周五盘后）、真利好词表、**「2.5 亿元但占比 0.15%」反例不算**、分红/回购/股权激励「实施完成」不撞重组落地、公告暂缺与无利好分开、观察股不进清单、占比解析（多值取最大、净资产口径不认）。
- 代码提交 `85c47f8`（main-dev）。

## 四、边界

- 占比取公告披露的最大「占股本/市值」口径；披露写法解析不出占比时按宁缺勿滥丢掉——**宁可漏，不误报**。线上若遇少见写法漏判，属预期行为，补正则即可。
- 「这两天」按自然日为今天 + 昨天；交易日表在手时回溯到上一交易日（覆盖周末/长假）。跨更长节假日的「未兑现」窗口不承诺。
- 真利好词表按标题关键词判定；调整口味（如把控股股东增持计划剔除、把回购注销门槛改到 1%）只改 `EventCoil.positiveEventKind` / `BUYBACK_CANCEL_MIN_PCT` 一处。
- 未接市值数据做相对规模比较，占比口径依赖公告自身披露；复盘利好清单不构成买卖指令，利好 ≠ 股价必涨。
