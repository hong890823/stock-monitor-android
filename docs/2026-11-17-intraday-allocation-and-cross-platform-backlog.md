# 盘中提醒分仓约束与 Android/mac 一致性：待优化清单

日期：2026-11-17（Asia/Shanghai）  
状态：Android 已实施本轮 P0 盘中提醒一致性与数量约束；跨平台对齐、真实成交配对及板块事实核验仍待实施；不是现行交易规则，也不是北方稀土的买卖指令。

## 1. 背景与证据边界

### 2026-11-17 尾盘清仓提醒复核后的规则修订（优先于下文旧的退出表述）

- 已从 Android 通知历史核实 14:35:55 的600股退出提醒；用户明确未清仓。历史估算亏损不是实际成交损益，不修改真实持仓、交易记录或分仓配置。
- Android 取消 `CRITICAL + 3根15分钟破位` 自动授权全仓退出的路径。`exit_position/exit_priority/risk_exit/stop` 一律输出零可执行股数的“重大风险待复核”，不自动改成减仓指令。独立减仓信号继续使用自己的证据和数量门控。
- CRITICAL 保留为风险标签，不再等同交易授权；市场/组合普跌、普通基本面红灯、自动失效价等会记录具体来源，但不能据此认定持有逻辑失效。第一版没有人工清仓授权入口，也不增加保证盈利或永不止损规则。
- 盘中和持仓复评两个通知入口共用复核通道，使用“重大风险待复核”标题，不显示拟卖全部股数、卖后剩余零股或卖出损益估算。正文记录采样时间、行情/日级依据日期、关键价位、最近已完成15/30分钟K线、风险标签来源及与上次复核的证据摘要对照。旧提醒缺少证据时明确无法比较，不编造新增恶化。
- 原同日计划的未执行部分进入 REVIEW_REQUIRED，保留历史目标、真实数量反馈及通知送达状态；不创建新600股卖单、不假定成交或生成接回额度。缺少独立人工复核恢复机制时，不自动恢复这类暂停计划。
- 最高风险优先级在计划准备、预约和通知出口再次阻断；加载旧最高优先级计划时转复核（已完成历史保留）。历史通知原文不删除、不篡改；变更仅在新版运行后生效。

## 2. 优化原则

建议统一决策顺序：

```text
新鲜行情与已完成 K 线校验
  → 个股/板块/市场证据与风险分类
  → 观察、普通滚动操作、风险减仓或退出
  → 分仓边界 + 今日可卖/可买资格 + 同日计划剩余额度
  → 数量、费用和收益复核
  → 同一个结构化结果生成通知、持仓卡片和报告
```

分仓不应把没有卖点的行情变成卖点；但必须影响最终可操作资格和数量，不能只在文案中写“保留底仓”。价格和走势先决定动作与风险，再在容量边界内决定规模。不要预设固定比例就是最优数量。

### 用户明确准则：同日建议连续、可执行，做 T 以净收益为前提

用户要求同一天提示的操作不互相矛盾、能够执行；如果提示做 T，应以获得正净收益为目标。以下作为后续实现与验收的核心约束，不表示当前程序已经实现。

1. **同一股票只有一个当前有效的操作结论。** 所有提醒入口先读取同日计划和执行状态，再形成新结论。不能让一个入口喊卖、另一个入口同时喊买或“不卖”，也不能把同一批股份重复分配给多个计划。
2. **一致性不是全天不许改变判断。** 新证据可以使观察升级为减仓，或使尚未执行的计划暂停/撤销；但必须写清旧计划、执行情况、新证据及新计划如何替代旧计划。只有报价波动而缺少新的确认，不应反复翻转动作。
3. **不把提醒当成交。** 未卖出不能生成做 T 接回容量；部分成交只处理实际已成交部分。净持仓变化最多确认数量变化，不能推导实际成交价；做 T 收益计算须取得可追溯成交价格、数量和费用，缺失则只观察。
4. **数量和价格必须当下可执行。** 同时满足分仓、实际可卖/现金、交易单位、有效报价、价格窗口、同日剩余额度和已有交易门控；报价超出窗口或计划过期即停止执行并复核，不能继续推送旧股数。
5. **做 T 的正收益指本轮配对交易扣费后的价差收益。** 不等于整笔历史持仓回本，也不等于卖出相对历史成本盈利。卖出前按保守接回价格计算预期净收益；必须覆盖双边佣金、适用税费、过户费、滑点及安全余量，并达到正的最低净收益门槛。参数和余量须在实施时显式配置和验证。
6. **接回时重新核算，不能只看当前价低于卖价。** 使用实际卖出成交净收入、实际可配对数量、此前已接回部分及新的买入费用/滑点预算，推导最高可接受接回价，再与走势和价格窗口共同校验。预计净收益不足时不发可执行做 T 提醒，不为了完成闭环而追高接回。
7. **不承诺实际成交必赚。** 行情跳变、滑点、未成交或无法接回均可能使实际结果偏离估算。文案分别标注“预期净收益”“实际已完成轮次净收益”“未完成轮次”，保留失败/失效记录；卖出后尚未接回不能记作已经赚到做 T 收益。
8. **风险处置不冒充盈利做 T。** 已确认风险减仓/退出独立执行风险规则，不以能否盈利为前提，也不因此前提示做 T 就强行接回；风险升级时明确终止或暂停原滚动计划并说明原因。

示例表达（非真实交易建议）：“原计划减 200 股，已确认成交 100 股；新证据使剩余 100 股计划暂停。已卖部分尚未满足接回条件，继续观察。”不能用一句“现在不卖”掩盖前序计划和执行状态。

## 3. 待优化项

### P0：普通滚动操作接入分仓硬边界

- [x] 将用户已保存的分仓配置及派生数量接入盘中链路和最终动作校验；系统推荐分仓不能未经确认覆盖用户配置。
- [x] 普通做 T/滚动止盈不得减少到用户底仓目标以下，同时不得超过今日可卖数量。
- [x] 在当前“分仓是数量目标、不是独立交易批次”的模型下，采用容量上限：`min(今日可卖数量, max(总持仓 - 底仓目标, 0))`，再应用策略额度、同日计划和交易单位约束。
- [x] 缺少分仓配置、配置损坏或风险观察模式时，普通做 T 不输出确定股数；必要的风险处置走独立分支。
- [x] 收紧数量后重新计算做 T 双边费用、滑点和最低净收益；小单达不到门槛时观察，不为达到门槛增加卖量。
- [x] 同日分仓/持仓反馈使旧数量计划失效时进入复核；未确认执行不当作已卖出，不产生虚构接回容量。

### P0：明确普通操作与风险处置的优先级

- [x] 观察状态不携带可执行卖量、买量；仅展示触发条件、缺失证据和下次复核条件。
- [x] 普通滚动操作遵守底仓保护；风险处置可独立涉及底仓，不把底仓视为永远不能卖。
- [ ] 为突破底仓保护定义独立、可审计的风险升级条件，说明涉及底仓多少股、为什么需要动用；仅有板块下跌或一只关联股跌停不能直接解除保护。
- [x] 严重风险退出不被分仓配置或做 T 收益门槛挡住，但仍须满足行情有效性、风险确认和实际可卖资格。
- [ ] 大跌、成本高或浮亏大均不能独立触发逆势加仓；买入继续通过现有趋势、完成周期、量价、资金和价格窗口校验。

### P0：用相同输入比较 Android 与 mac

- [ ] 保存两端实际运行版本、提醒时间、报价时间、行情来源、已完成 K 线时间、支撑/风险线、日级风险、确认数、持仓/可卖数量、分仓版本和同日计划状态。
- [ ] 明确区别“连续行情采样轮数”和“不同已完成 15 分钟 K 线数量”；同一根 K 线不能因反复刷新而增加确认数。
- [ ] 复现 mac 的“10:00:20 观察 → 10:00:40 减仓”，核对缓存新鲜度、入口差异与状态更新；在证据不足时保留未知原因。
- [ ] 对普通风险 2/3 根确认、高位转弱、CRITICAL 退出、承接缩量、深套及不足一手等分支逐项对齐，不能只复制一端的一个阈值。
- [ ] 使用同一份固定证据运行两端策略，比较动作、股数、原因和失效条件。更保守或提醒更早均不自动代表更正确。
- [ ] 在回放与测试后确定统一确认门槛；本记录不批准直接把 Android 改成所有风险一律等三根。

### P1：纳入经过验证的板块联动证据

- [ ] 区分北方稀土（600111）与中国稀土（000831），验证关联板块及所用同业的代表性，不把同名题材股票自动视为龙头。
- [ ] 对关联股跌停/开板、板块下跌广度、相对强弱及资金信息记录交易日、时间、来源与新鲜度。
- [ ] 板块信息用于风险增强、限制新增或提示观察；如何调整风险级别/确认门槛须另行定义并验证，不能凭未核实消息直接加快卖出。
- [ ] 区分个股自身结构破坏与板块联动下跌。相关性不作为已证实的因果；数据不足时显示“板块联动待核实”。

### P1：通知统一表达状态变化与数量来源

- [x] 同一股票同日使用统一计划和状态；风险升级时说明替代关系，并明确未把旧计划当成交。
- [ ] 若只是旧缓存补齐而非市场出现新变化，应如实说明“完成 K 线数据已补齐”，避免制造行情 20 秒内反转的印象。
- [x] 可执行提醒显示动作性质、同日计划连续性、最终建议量和风险/做T的不同口径；底仓和可卖资格按最终门控计算。
- [x] 通知、详情和报告采用最终回调动作结果，最终降级观察不泄漏原始策略股数。
- [x] 提醒数量是计划，不是成交；重复提醒、部分执行、反向变化和 CAS 竞态遵守同日计划规则。

## 4. 验收场景

以下均为合成数据，不代表用户实际持仓或当天行情。

| 场景 | 预期 |
| --- | --- |
| 总持仓 800、底仓目标 600、今日可卖 800；普通做 T 原计划 300 | 最多 200，且按 200 重新验证净收益；不通过则观察 |
| 总持仓 800、底仓目标 600、今日可卖 100 | 最多 100，不把滚动容量当作可卖批次 |
| 总持仓等于或低于底仓目标 | 普通滚动卖出为 0；必要风险处置单独评估 |
| 未设置/损坏分仓，或风险观察模式 | 普通做 T 观察；风险提示和合格的风险处置不被吞掉 |
| 滚动容量不足一手或收紧后净收益不足 | 观察，不扩大数量凑手或凑收益 |
| 已确认严重风险且主要剩底仓 | 按明确的底仓突破政策复核，解释原因，受可卖量封顶 |
| 同一根 15 分钟 K 线连续刷新三次 | 仍只算一根确认，不升级为三根 |
| 板块关联股跌停信息过期/无法验证 | 不作为当天已确认事件，不自动提高卖量 |
| 仅发生大跌、尚未完成买入确认或现金不足 | 不输出逆势买入数量 |
| 两端加载相同风险、K 线与仓位快照 | 按统一规范得到相同动作与数量，或暴露明确的差异原因 |
| 观察升级减仓、减仓后部分执行、同日再次触发 | 展示状态变化及剩余计划，不重复扩大卖量，不假定成交 |
| 行情日期错误、完成 K 线缺失、账本不一致 | 不生成可执行数量，不绕过现有门控 |
| 两个提醒入口同时对同一股票生成相反动作 | 统一计划仲裁，只发布一个有效结论；替代关系和证据可追溯 |
| 原计划卖 200，确认成交 100 后风险解除 | 暂停/撤销未执行部分；不否认已成交部分，不自动接回 |
| 提示卖出但没有实际成交反馈 | 接回容量为 0，不生成虚构做 T 利润 |
| 只反馈净持仓减少，未提供成交价格和费用 | 不推算实际卖出价，不据此声称接回能盈利 |
| 接回价低于实际卖价，但双边费用后净收益不足 | 不输出可执行做 T 接回建议 |
| 部分卖出/部分接回，多次成交有最低佣金 | 按可追溯配对数量及相应实际/保守费用重算，不重复使用已配对数量 |
| 价格回升超过最高可接受接回价 | 停止原接回计划，不为补齐持仓而追价 |
| 历史持仓浮亏，但已完成一轮做 T 价差净收益为正 | 分开展示历史持仓盈亏与该轮净收益，不宣称整仓回本 |
| 做 T 未完成或实际成交收益为负 | 如实保留结果，不删失败记录、不标为“已盈利” |
| 做 T 计划期间风险升级 | 风险处置优先，暂停/终止接回；说明与原计划的关系 |

## 6. 本轮 Android 已交付与明确延期

已交付：

- 普通做T必须有已保存的普通分仓配置；数量上限为 `min(今日可卖, max(总持仓 - 底仓目标, 0))`，向下取整到一手；风险观察仓、缺失配置和滚动仓不足一手只观察。
- 数量收紧后按最终股数重新计算双边费用、滑点和最低净收益；不得复用更大股数的旧收益批准，也不把预期净收益写成实际盈利。
- 同日计划具备剩余量、风险优先级和连续性说明；已通知/预留/完成/待复核计划不重复发送，普通反向信号不取消更高优先级风险计划；风险升级可替代低优先级计划但不伪造已成交数量。
- 通知回调按计划剩余量重新生成正文；预留后的严格价格窗口补仓再次执行交易门控；计划 CAS 失败不再向上层报告发送成功。
- 风险退出与普通做T分离：风险处置可涉及底仓，不受做T净收益门槛阻挡，但仍受行情证据、T+1 和实际可卖数量约束。

明确延期：真实成交价格/费用配对与接回容量、观察状态自动恢复/撤销、macOS 端规则修改、跨平台固定证据回放、未经核验的关联股跌停联动。
